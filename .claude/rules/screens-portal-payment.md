# 门户 · 下单、支付与订单

- 确认页的意图由地址决定（`checkout/model.ts` 的 `parseTarget`，地址见 screens-portal.md）；入口页只拼地址不判模式。
- 确认页按样稿 v5 `#p-checkout` 是两栏（959 以下一栏）：左栏「这一份」小卡（续费 / 新买 / 叠加 / 重置，`copy.item`）或「现在 → 换成」（换套餐，`copy.swap`）、会发生什么、买多久、算式、起名、提示、退路；右栏账单卡（`checkout/Bill.tsx`）依次是明细（「原套餐没用完的部分」可展开「怎么算的」）、优惠码、余额开关、要付多少、付款方式（复用 `common/PayFlow.tsx` 的 `PayMethodPicker` / `pickMethod`，不另写）、主按钮。测试按整段文字匹配的几句（`#pay-summary`、算式、会发生什么的每一行、每条提示）各自单独成一个元素。
- 换套餐的「原套餐没用完的部分」照 Go `order/service/proration.go`（审计 #3）：原份是订阅套餐只按剩余付费时间算（`credit_detail` 的流量两项为 0，送的天数不算钱）；一次性取剩余天数与剩余流量（上限不含送的）里少的那个，永久的只看流量；比例与钱都向下截断。「怎么算的」按原份种类写（`checkout/copy.ts`），mock 的 `creditOf` 同口径。换套餐的会发生什么写「每期流量 A → B」（审计 #15）；重置的「重置后能用」是上限 + 送的（送的流量重置后保留）。
- 金额全取报价接口（`common/quote.ts`）：余额开关默认打开，只在 `with_balance` / `without_balance` 两组数之间切换；Forced 锁成打开；Kept 时紧挨金额写「最低要付 ¥1.00，所以这次余额只用 ¥x」；只有换套餐抵扣后 ≤ ¥0.99 的零头免掉（`small_due` + `waived`，结果页写「零头 ¥0.xx 已免」）；其余用尽余额还差的低于最低额时 `below_minimum` 为真：余额行锁成「已全用上」，按钮置灰「余额不够，先充值再来」，写明还差多少、在线付款最少多少，给钱包入口（后端下单 422）。用过的优惠码记在地址 `?coupon=`，充值回来还在。文字在 `checkout/copy.ts`
- 建单带 `as_of` 与 `expect {total, balance_applied, payable}`，`use_balance` 传这一档用掉的余额；409 `quote_changed` 重新报价并标「已更新」，用户再点时请求体变了、按指纹换新幂等键；409 `order_pending`（`fields.order_id`）给「取消它 / 去付款」，那张已超过付款期限（`fields.lapsed` 为 `"true"`，`common/quote.ts` 的 `refusalOf`）时只给「取消它」；付款页发起支付回 409 `order_lapsed` 时给「取消这张单，重新下单」，取消后回选购页（`isPaymentLapsed`）。这几个码（含下面的 `payment_in_progress`）都登记在 core 的 `SERVER_ERROR_CODES`，一律按码与 fields 认，不匹配文案
- 付款是一页（`#/checkout/pay/<订单>`，`common/PayFlow.tsx` 的 `PayPanel`，订单页与钱包的弹层也用它）：手机主按钮「打开支付宝付款」、二维码收进「用另一台手机扫码」；电脑直接给收银台地址的二维码，二维码之下是次按钮「在这台电脑上付款」并写一句用途（`payHereNote`：支付宝「没带手机？在这台电脑上用支付宝网页付」）；放不进 40 版时退回「打开付款页」；3 秒查一次订单，付完自动去完成页，没更新再点「我已付款」（`POST v1/orders/{id}/query`）。订单页与钱包的弹层是 kit 的 `Sheet`（`PaymentModal`）：订单页「去支付」先进 `choose`（标题「去支付」：订单名与单号、应付，`PayMethodPicker` 选方式，按钮「去支付 ¥所选方式的合计（含手续费）」，有余额时下面是「改用余额付」，最下面「稍后支付」），选完进付款面板。付款方式单选行（样稿 `.pays`）只有一份：`PayFlow.tsx` 的 `PayMethodPicker` + `pickMethod`（钱包充值与订单页共用；支付宝 / 微信支付用品牌色「支 / 微」小方块 `MethodMark`，其余渠道用通用卡片图标）。
- 完成页（`#/checkout/done/<订单>`，`common/Result.tsx`，560 宽居中，「发生了什么」h3 紧跟 ul）分「发生了什么 / 你要做的 / 没变的」；新买一份把新链接与「添加到 App」放最上面。落到哪一份按订单详情的 `subscription_id` 认（`result-copy.ts` 的 `doneSub`；履约后才有，新购没履约时不猜，续费等先用地址里的 `sub`）。换套餐的「在 App 里点一次更新」旁边给 `common/UpdateHelp.tsx` 的链接，去帮助中心这台设备那一段
- 下单幂等键按请求体指纹复用：双击、失败重试、关掉支付弹窗后再点都回放同一张订单，改了任何参数才换新键。
- 刚下的待支付单记住 30 分钟（确认页是跨页面的 `checkout/model.ts` 的 `placedOrders`，指纹去掉 as_of / expect；充值是 `usePlacedOrder`）：同样的意图再点时先 `recallPayable` 问一次还能不能付，能付就重开它的付款、不下第二张（否则余额冻结两次）；已取消、超时或付掉就 `forget()` 按新请求下单。
- 发起支付失败怎么办在 `common/payRetry.ts`（`payFailureAction` / `afterOrderCheck`），`PayPanel` 按它做：
  - 409 `payment_in_progress`（同一张单上一次还在去渠道建单）：不 `forget`、不调 `onUnpayable`，显示「正在发起支付，请稍候…」，按 `PAY_IN_PROGRESS_BACKOFF_MS`（2/5/10 秒，合计 17 秒，要盖过后端建单最长 15 秒）自动重发，最多 `PAY_IN_PROGRESS_MAX_RETRIES`（3）次，用完显示错误加「重试」；定时器卸载时清掉。
  - 409 `conflict`（这次发起被新的发起取代，或订单状态变了）：先 `order.refetch()`；仍是 pending_payment 就写「这次付款已被新的发起取代，请重试。」并给「重试」，不是待付才调 `onUnpayable`（`forget`）；刷新失败只显示错误加「重试」。
  - 409 `order_lapsed`：调 `onUnpayable`。
  - 409 `below_method_minimum`（应付低于所选方式的最低额）：只显示后端原话，不刷新订单、不给「重试」，靠「换个付款方式」；必须排在 `conflict` 前面判（守卫 `payRetry.test.ts`）。
- 去收银台只做顶层 GET 导航：POST 跳转要自动提交表单，会被入口页 CSP 的 `form-action 'self'` 拦下。支付成功后失效 `['portal']` 前缀下全部查询。
- 「我已支付，刷新状态」（`POST v1/orders/{id}/query`）只对发起过支付（行上 `has_payment_intent`）的单显示，不带幂等键；结果归成已到账 / 渠道尚未确认 / 查询失败三种（订单已关闭才到账的钱也算已到账、引导提工单），显示在待支付卡下面的结果条里，到账另弹 toast。
- 订单状态只用库里的 5 态（`00013_order.sql`：pending_payment / paid / fulfilled / cancelled / expired）；不做退款，没有 refunded / partially_refunded，也没有 draft / processing（传了后端回 400）。发起过支付等回调的单仍是 pending_payment（看 `has_payment_intent`），待支付卡片只取 pending_payment。
- 订单页（10-16 样稿）：
  - 待支付卡置顶（`orders/Pending.tsx`）：与外框侧栏待支付数同一个查询（`portal/queries.ts` 的 `PENDING_ORDERS_KEY`，`common/orders.ts` 的 `useOpenOrders` 只换 select；schema 与键只在 queries.ts 定义一份，common/orders.ts 转出）。头一行「待支付 N 笔 · 30 分钟内不付会自动取消」（N = `counts.open`），卡上倒计时「N 分钟后自动取消」每 30 秒重算；动作「去支付」、发起过支付才有的「我已支付，刷新状态」、`cancellable` 才有的「取消订单」。取消确认写明退回什么（`cancelBody`：用过的优惠码、冻结的余额各自写，都没有写「这张单作废，没有扣钱」）。
  - 已结束：筛选「全部 / 已支付 / 已取消」带计数（`counts`，不受当前筛选影响）、按下单月份分组（组头写该月已加载行里已支付的合计或「无支付」）、「显示更早的订单（还有 N 笔）」每次多取 6 条，不用分页器；从没下过单只写「还没有订单」与「去选购套餐」，不画筛选条。
  - 展开由地址驱动（`#/orders/<id>`，点行切换用 replace），不在已加载列表里时单独成卡；`?paid=1` 弹支付确认（3 秒轮询、最多 2 分钟），关掉后抹掉 paid。
  - 收据（`orders/Receipt.tsx`，数据由 `common/orders.ts` 的 `orderReceipt` 给）：第一行结果（「已续上 / 已开通，有效期至 …」等；后端取消原因只认 user_cancelled / expired / plan_archived，认不出的英文码写「已取消」，后台写的中文原因照写）；金额行「原价 / 优惠（券码）/ 用了余额 / 实付」。「实付」是渠道实收（`payments` 合计，与完成页 `paidText` 同口径），不用 `paid_amount`（库里恒等于订单总额、含余额那部分），全部用余额付写「全部用余额」；换套餐单（upgrade）的总额里扣了原套餐没用完的部分、详情里没有这一项，前端不用差值去算：写「订单金额 = total_amount」，优惠只作「其中优惠」说明，再列余额与实付；取消 / 超时的单写「用了余额（已退回）」，待支付写「还要付」。下面是支付记录（付款方式的叫法、时间、成功、金额）、订单号与「复制」、「对这笔订单有疑问？提交工单 →」。
- 钱包（10-16 样稿）：余额主卡（kit `Hero`：大号金额、「充值」「兑换卡」）；余额记录按月分组、不算月度合计（只拿得到最近 100 条），先显示 8 条、「显示全部 N 条」。每行标题按 kind（`wallet/model.ts` 的 `ledgerView`），副行只写时间加按 kind 的固定短语（下单用余额「结账时先用余额」、取消退回「订单没付成，余额退回」、换套餐退回「差额退回」、礼品卡「兑换余额卡」），**不显示后端 memo**（那是对账用的原话，带「剩余价值」、原因码 user_cancelled 等），只有人工调整（`balance_adjusted`）显示 memo（管理员填的原因）；挂账类流水按保留规则 6 称「待处理到账转入」（界面不写「挂账」）。最下面「兑换过的卡」（`GET v1/me/gift-cards`）。
- 充值是钱包页上的弹层（`wallet/Topup.tsx`，样稿 `#sh-topup`）：大号金额、¥50 / 100 / 200 / 500 / 其他、「最少 ¥X，单次最多 ¥50,000」（X 取 ¥1 与各方式最低额里最小的两者较大的；一个方式都付不了当前金额时主按钮灰着写「至少充 ¥X」）、付款方式（`PayMethodPicker`，手续费按停手 300 毫秒后的金额报价）、按钮「充值 ¥金额」；建单 `POST v1/me/topups`（响应 200 不是 201）成功后充值弹层收起、付款弹层接上。
- 礼品卡兑换是钱包页上的两步弹层（`wallet/Redeem.tsx` 的 `RedeemSheet`）：地址 `#/wallet/redeem` 直接打开它（我的套餐「有卡？去兑换」与外部链接在用），关掉回 `#/wallet`（replace）；第一步输卡号「兑换」（先 preview），第二步标题是 preview 的 `placement.question`（多于一个选项时）或「兑换这张卡」，卡面写卡种（`giftKind`）、`giftFace`、卡号；选项与默认值来自 preview 的 `placement`，没有默认值时按钮置灰「先选一种用法」，兑换带 `choice`（幂等 `gift_card_redeem`），可「换一张卡」回第一步。成功后失效整个 `['portal']` 前缀，地址换成 `#/wallet/redeem/done`（replace）整页显示结果（`RedeemResult`）；完成页按选定的用法自己写，不显示服务端 summary（话术里有「订阅」等词）。直接打开 `#/wallet/redeem/done`（没有结果）时当作 `#/wallet/redeem`。
- 支付手续费（00042）：渠道可向用户加收「固定 + 比例」手续费，用余额付不收。三处选付款方式（确认页、订单页弹窗 `Choose`、钱包充值）都用 `usePaymentMethods(应付分)` 取带 `fee` / `total` 的方式列表，文字统一走 `common/fee.ts`（`feeLine`、`feeRule`、`minLine`）；付款面板显示发起支付回来的 `amount`（含手续费）并在下面写「含手续费 ¥x，订单 ¥y」（`surchargeNote`）。订单的应付、总额与完成页的「付了多少」不含手续费。
- 确认页 `?reset=<一份>`（`model.ts` 的 `reset` 目标）：报价 `action: 'reset'`，建单 `POST v1/me/subscriptions/{id}/traffic-reset`（幂等 `order_create`，体只有余额 / 优惠码 / as_of / expect），没有「买多久」；完成页 `k=reset`。
- 没有会员折扣、没有币种（10-16 删）：报价行 `total = subtotal − discount − credit`，`discount` 只含券；订单行 / 详情 / 建单 / 充值响应都没有 `currency`、`member_discount_amount`，金额一律 `formatMoney(分)`。流量重置（`target.kind === 'reset'`）永远按原价：确认页不显示优惠码输入，报价与建单都不带券码（用户 10-14 定）。
- 付款方式各有最低付款额（`GET v1/payment-methods` 每项的 `min_amount`，分）：报价与建单按所有方式里最小的判（报价的 `min_payment`，`below_minimum` 那套），发起支付按所选方式判。三处选付款方式（确认页 `Bill`、订单页弹层 `Choose`、钱包充值）都把应付（不含手续费）传给 `PayMethodPicker` 的 `amount` 与 `pickMethod` 的第三参数：付不了的方式置灰、不可点、小字写「这个付款方式最低 ¥X」（`minLine`），默认选第一个付得了的；确认页 keptNote 只列付得了的方式（`usableMethods`）；订单页弹层一个都付不了时写「这张单的金额低于现在所有付款方式的最低额……改用余额付」。
- 买套餐先选落点（10-16）：`#/checkout?plan=<套餐>` 有份时显示 `checkout/Landing.tsx` 的 `LandingChooser`，选项来自 `GET v1/me/checkout/landings?plan_id=`（`common/landings.ts`），不预选；`model.ts` 的 `landingChoice` 决定：只有一个可选项且没有置灰项时 replace 跳过去（`landingHref`），否则全部列出；落点接口 409（套餐关了新购）原话显示加「去选购」。
- 每人份数上限（后台「购买限制」）：到了上限时落点里另开一份那项带 `disabled_reason`，`ChoiceList` 的 `disabled` 置灰、说明行写原话；一个可选项都没有时标题换成「{套餐名}现在不能再开一份」并给「去我的套餐」。确认页报价回 409 `subscription_limit_reached`（`common/quote.ts` 的 `isSubscriptionLimit`）时显示「不能再开一份了」+ 原话 +「去我的套餐」，不当「价格加载失败」。
- 叠加（一次性同款）：`#/checkout?stack=<一份>`，报价 `action: 'stack'`，建单 `POST v1/me/subscriptions/{id}/stack`（幂等 `subscription_stack_create`，体 `price_id / use_balance / coupon_code / as_of / expect`）；订单 `kind=stack`，标题「叠加 · 套餐名」，完成页 `k=stack`「叠加好了」。一次性套餐的报价行带 `validity_days`（null = 永久），到期写「永久有效」不写日期。订单种类只有 new / renewal / topup / upgrade / stack / traffic_reset。
- 礼品卡落点（`wallet/model.ts`）：套餐卡是一次性套餐时，同款生效中的那份给「叠加到…」（`stack`）；`new_permanent` 为真写「永久有效」、不写到期日；卡面一次性写「套餐名 · 一次性 · 有效 N 天 / 永久有效」。送流量的卡（`traffic_bytes`）与加时长、重置一样必须落在一份在用的套餐上（Go `grant` 的 needsSub），没有就不能兑；送的流量按时间的套餐只在本期有效、一次性加到总量上，话术照这个写。
