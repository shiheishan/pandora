# 后台 · 用户

- 页签只有三个：用户列表、用户组、批量运营（10-16 设计稿）。注册设置与设备策略是本目录导出的组件，由别的模块接：`SignupGrowth`（营销）、`SignupSecurity`（安全）、`DevicePolicy`（安全），组件头注释写着用途与 props；用户模块的 `index.tsx` 不再接它们。会员折扣、流量重置统计页与重置历史、用户级「加时长」「加流量包」已删（10-16）。
- 保留规则 2 贯穿整个模块：后台看不到订阅地址。列表、详情、画像都不含令牌；「订阅与设备」页签顶部用一句 Callout 代替设计稿的「订阅地址 + 复制」；换发订阅链接的响应 schema 用 `.strict()` 守住「不回令牌」（`model.test.ts` 断言带令牌即判不符），成功后提示让用户到用户端重新复制。换发会连节点密码一起换（2026-10-07），对话框写明旧链接和已导入的节点立即失效、用户所有设备要重新更新订阅；后台换发不限频。换发从订阅表那一行的「操作」菜单进（`RotateDialog` 的 `subscriptionId`），候选口径仍是 `rotatableSubscriptions`。
- 明文注册 IP 只从风控画像接口取。
- 产品取舍：重置密码是管理员直接设新密码，不要原因、不发邮件、不回显（D-B-2）；不给全局「默认同时在线设备」滑块；批量生成不带「开通套餐」（引导去人工开单）；设备只有在线台数与上限，不列逐台客户端与 IP（节点只上报 IP 哈希，D-B-8）；识别窗口只给 5 / 10 / 30 / 60 分钟（`DEVICE_WINDOWS`），下拉旁说明代价。
- 列表（样稿 admin-v4 `#p-users`）：列顺序 用户 / 状态 / 套餐 / 本期流量 / 余额 / 设备 / 用户组 / 最近登录；筛选是搜索 + 「账号状态」「用户组」两个下拉，右侧只写「注册时间 · 新的在前」（不排序，后端不支持）；表尾只显示后端给的总数与翻页。状态列用 `detail.ts` 的 `listStatusView`（账号正常但当前订阅已过期写「已过期」，与 sub_state 筛选同口径）。页头计数 `PageCount` = 总数；列表上没有「批量生成」入口（在「批量运营」里）。点行进详情页，地址带着列表的查询串，详情页的返回链接回到原筛选。
- 用户详情是整页（kit `DetailPage`，`users:list` 已在外框登记为详情路由），地址 `/users/list/<id>/<页签>`，资料不写进地址；有详情 id 时 `index.tsx` 只渲染详情不渲染列表。页头：头像、邮箱、短 ID + 复制、账号状态圆点，管理员 / 封禁标签；右侧「续费这一份（一次性写「给这份开单」）/ 加流量 / 调整余额」——前两个作用在生效中、到期最晚的那份（`detail.ts` 的 `headerTarget`），没有就灰着写原因；「调整余额」切到「订单与余额」并展开 `BalanceForm`。已注销时页头无操作。已注销说明与后台备注是主栏顶部的 Callout，四个页签下都在。右栏（`UserSide.tsx`，四个页签都显示）：邮箱（验证 + 修改）、Telegram（没设用户名时后端给空串，写「已绑定（无用户名）」，不写孤零零的「@」，报告 2.3-8）、最近登录（带近 7 天 IP 数）、用户组（调整 → `GroupPicker`）、余额（调整）、注册时间、邀请人（修改）、显示名与备注（修改）、登录密码（重置）、身份。资料页签（`ProfileTab.tsx`）：统计、当前套餐卡（`planMetaLine`）、最近 3 单（「查看全部」切页签）、处置区（正常时 DangerRow 禁用账号，禁用 / 封禁时 Callout + 启用；非管理员再有注销账号）。
- 风控页签（`RiskTab.tsx`）：评估四项——风险等级（画像顶层 `risk` → `PROFILE_RISK_VIEW`，后端按共用 IP 用 `clusterRisk` 推出，与「安全与运维 › 风控」同一规则；不读 `users.risk_level`，那列没有代码写）、注册 IP、近 7 天用过的 IP 数（`loginIps7d`：画像 `ips[].last` 在近 7 天内的去重 IP 数，前端算，≥ `LOGIN_IPS_WARN` 标警示）、共享 IP 聚类（`related`，有无都带一句灰字解释）；评估标题右侧「看审计记录 →」（`#/security/audit?q=<用户 id>`：id 精确匹配操作人或对象，邮箱是包含匹配会混进别人）。下面「最近使用的 IP」表（画像 `ips[]` 是本人所有操作——登录、改密码、下单等——的 IP，不只登录；按 last 倒序 `recentIps`；列：IP、归属地（`geo` + `networkLabel`）、次数、首次、最近、同 IP 账号（有 `risk` 时带风险标签））；标题右侧「看登录记录 →」（`#/security/access?view=login&user=<id>`，含冲着他的匿名登录失败）；没有共享时一句 Callout 指向「安全与运维 › 风控」。「最近使用的 IP」下面是「最近订阅拉取」（画像 `fetches[]`，最近 50 次）：IP 默认打码（文件内 `maskIp`，与 identity `maskIP` 同口径），「显示完整 IP」只在组件内切换、不另发请求（打开画像时后端已记查看审计）；结果文案 `fetchResultLabel` 对应拉取日志的 ok / expired / rate_limited / error / not_found。画像 schema `profileSchema`（含 `ProfileRisk`、`ProfileIpActivity`）放在纯 zod 的 `schemas.ts`，假后端用例（node 侧 tsconfig，不能 import 带 React 的 api.ts）直接用，api.ts 转出。
- 设备策略（`DevicePolicy.tsx`，挂在安全 › 风控下方）：宽容值、设备识别窗口的 `hint` 就地解释（宽容值只对「超限停止下发」生效，超过「上限 + 宽容值」才停）；超限列表的「已超限 / 宽容内 / 已满」标签带 `title`。
- 用户组删除拦截先看节点池名单（`exclusive_pools`），再看成员、套餐可见、优惠券，与后端 409 同序（`model.ts` 的 `groupBlocker`）；删除确认用固定文案 `GROUP_DELETE_NOTICE`（10-16 起没有组专属价）。删组、启停后连套餐页（`['admin','plans']`）与订阅域名页的用户组查询一起失效。新建与编辑都是弹窗。
- 用户组停用 / 启用（`POST v1/user-groups/{id}/status`，`{disabled}`，无 reauth、无幂等）：停用要确认（`GROUP_DISABLE_NOTICE`：已有成员不受影响，只是不能再加人、下拉里不再出现），启用直接做。所有「分配 / 选择用户组」的下拉与勾选（用户详情分组、批量生成、套餐可见组、节点池仅限用户组）用 `assignableGroups(groups, 当前值)` 隐藏停用组但保留当前已选的，名字用 `groupOptionLabel`（停用的加「（已停用）」）；筛选类下拉（用户列表分组筛选、批量运营按条件筛选）不隐藏，只标「（已停用）」。公告定向的组列表来自 content 后端，不带 status，暂未区分。
- 前端口径与后端逐一对齐，改后端这些函数时同步改 `model.ts`：当前订阅挑法 = subscription service 的 `currentIndex`（`panel/internal/module/subscription/service/state.go`）；套餐类型按流量配额周期认（`planKind`：`total` 是一次性，= subscription 服务 `trafficPeriod`），永久 = 期末晚于现在 + 50 年（`isPermanent` = `IsPermanent`）；批量生成校验 = identity service 的 `normalizeGenerateInput`（`ops_generate.go`）；密码预检 = identity service 的 `validatePassword`（`password.go`）。
- 设备策略请求体：strict 才带 grace，识别窗口改了才带 `window_minutes`。
- 订阅只有 `active` / `expired` 两态（`00011_subscription.sql`）：「还在用」只有一处判断 `model.ts` 的 `isLive`（`status === 'active'`），不要另写状态集合；换发链接的候选是 `rotatableSubscriptions`（还在用的，一个都没有时退回全部）。
- 加时长口径（与 `subscriptionExtendable` / `extendSubscriptionTx` 一致，`model.ts` 的 `extendableSubscriptions`）：可选生效中、过期不满 30 天（`RENEWAL_WINDOW_DAYS`，按周期末推算）且有到期时间的订阅；永久的一次性不给加时长、改到期。救回（已过期，`isRescue`）要二次确认「已过期 N 天，延长后旧链接恢复可用」。
- 订阅与设备页签（`tabs.tsx` 的 `SubscriptionsTab`）：每份订阅一行（当前订阅排第一）：备注名优先 + 版本、类型与到期、流量与设备（在线台数 / 生效上限）、状态、「操作」。用 kit `RowList` 装进带框盒子而不是 ui `Table`——`Table` 的横向滚动容器会裁掉行内的弹出菜单。每行「操作」菜单（ui `Menu`）的项与灰着的原因来自 `detail.ts` 的 `subActions`：加时长、改到期、加流量、重置流量、改流量上限、改设备上限（`DeviceLimitDialog.tsx`：具体台数 / 不限 / 恢复套餐默认）、续费这一份（一次性写「给这份开单」，跳 `#/billing/orders?new=<用户 id>&sub=<订阅 id>`，要同步 `billing/OrdersTab.tsx`）、换发订阅链接。已注销用户没有操作列。设计稿的逐 IP 在线设备表后端没有，不做。
- 加流量（`GrantTrafficDialog.tsx`，`POST v1/subscriptions/{id}/traffic-pack`，路径沿用旧名，reauth + 幂等）：只对还在用的这一份；送的量订阅套餐加到本周期上限、周期结束作废，一次性加到总量上；按 GB 整数填、提交字节（上限 10240 GB）；回执 `bonus_bytes` 是这一份本期送的量合计。没有流量包、没有「未分配」余量。
- 重置流量（`SubEditDialogs.tsx` 的 `ResetTrafficDialog`，`POST v1/subscriptions/{id}/traffic-reset`，reauth + 幂等）：只重置点的这一份，原因 5–500 字。
- 停用 / 封禁 / 启用确认框（`dialogs.tsx` 的 `StatusDialog`）以后端为准写三段：立即生效（会话失效、节点断开、套餐不能用、到期照走不顺延）；用户再登录时口令对看到「账号已停用」、口令错仍是「邮箱或密码不正确」，找回密码收不到邮件；停用与封禁效果一样、只是记的状态不同。启用写「可以重新登录，没到期的套餐恢复可用（停用期间的时间不补）」。改后端口径（module-identity「账号枚举防护」）时同步这里。
- 调整余额（`dialogs.tsx` 的 `BalanceForm`，在「订单与余额」页签里展开）：「增加 / 扣减」单选 + 正金额（`balanceCents`），提交前确认框，原因必填，标签「原因（用户能看到）」（原样显示在用户钱包「人工调整」流水里，用户 10-21 定不拆字段）；请求体只有 `{ amount, reason }`（只有人民币）。
- 余额流水（`BalanceEntries.tsx`，用户 10-21 定做、只读，推翻 10-16「不做」）：「订单与余额」页签里余额区（含 `BalanceForm`）与订单区之间，`GET v1/users/{id}/balance-entries`（ledger，只要登录，不要 reauth；每页 `BALANCE_ENTRIES_PAGE` = 20，表尾 `Pager`），与用户端钱包是同一个科目的同一批分录。列：时间、类型、金额（正负，入账绿色）、变动后余额、原因 / 订单（有 `order_id` 链到 `#/billing/orders/<id>`，订单号取 `recent_orders` 里的，找不到写「查看订单」；memo 后台原样显示）。类型中文名 `model.ts` 的 `balanceKindLabel` 与用户端 `portal/screens/wallet/model.ts` 的 `LEDGER` 逐条一致（守卫 `model.test.ts`「余额流水叫法」），改一边同步另一边。调余额成功后 `useInvalidateUsers` 连流水一起刷新；订单变动跟 `orders.changed`。
- 订单状态叫法与用户端一致（报告 2.3-13）：`ORDER_STATUS_VIEW` 的 `expired` 写「超时取消」（用户端归「已取消」、结果写「超时未支付，已自动取消」；订单页「已取消」筛选同样含 cancelled 与 expired；状态列 80px、标签不换行，所以不写长叫法）；这张表由订单页共用。付款方式 offline 两边都叫「线下收款」。
- 批量导出没有 cookie，只能 fetch 带 Bearer 取回再存文件，要 reauth。
- 用户相关的地址被别处引用：仪表盘排行、工单「查看用户」、订单抽屉、⌘K 都跳 `#/users/list/<用户 id>`，订单标签跳 `#/billing/orders?user_id=`；改地址格式要同步这些入口。
- 批量运营是上下两张卡、各三步（批量操作用户：筛选 → 命中名单〔预览表〕→ 三张操作卡选一个〔导出 CSV / 群发邮件 / 批量封禁〕再在下面填；批量生成用户：账号格式 → 归属与原因 → 提交）；生成记录是表格（最近 5 次，结果列 `jobs.ts` 的 `jobResultView`），进度条用 `--info`。批量生成是后台任务：提交回 202 与任务，`useGenerationJob` 轮询到结束为止，进度条按 completed/total；结果 CSV 只能从服务端下（`requestRaw`，只有提交人、要 reauth、24 小时内）。任务与加流量的 schema 在 `opsSchemas.ts`，用户列表行、详情与重置回执的 schema 在 `schemas.ts`（都不依赖 React，node 侧的假后端测试只从这两个文件取 schema，不 import `api.ts`）。
- 注册设置（`SignupForm.tsx` 的 `SignupSettingsPanel`，`section` 为 growth / security；`signupSettings.ts`）：GET / POST `v1/settings/signup`，只发改了的字段（`signupBody`），所以两个组件互不覆盖；secret 只写不读（`captcha_secret` 发空串表示清除）；邮件链接登录在没配发信时禁用。
- 已注销（`status === 'deleted'`）：列表与详情标题一律 `userLabel`（「已注销 #<短 id>」，不显示占位邮箱）；详情顶部一句说明，没有任何写入口。注销对话框要填原因并输入该用户邮箱才能点，管理员不显示「注销账号」。
- 写操作：改邮箱、改邀请人（按邮箱精确找人，留空清除）、注销要 reauth；显示名与备注不要。原因 5–500 字，fields 标到对应输入框。「改到期」「改上限」只对生效中的那一份（`SubEditDialogs.tsx`、`subEdit.ts`，上限按 GiB 填、提交字节、留空为不限，最多 10 TiB）。
- 批量封禁（`BulkBanForm.tsx`）沿用批量运营的筛选：至少一个条件、带预览人数 `expected_total`、二次确认、幂等键；人数变了后端 409，要重新预览。
- 手机（≤ 639）各表只留两三列（`hideOnMobile`，照样稿 `.h-m` / `m-only`）：用户列表留「用户」（第三行并进套餐 · 到期）与「状态」；用户组留名字、成员与「查看成员」（编辑、停用 / 启用、删除在手机上不显示，同样稿）；最近订单 / 订单表留订单号、金额、状态；最近登录 IP 留 IP 与最近；生成记录的时间并进原因格。详情页头三个按钮与「新建用户组」带图标（`Button icon`：CalendarAdd01Icon、ChartHistogramIcon、Wallet01Icon、PlusSignIcon）。
