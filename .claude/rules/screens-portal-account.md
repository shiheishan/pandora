# 门户 · 账号安全

- 快捷登录（保留规则 1）：只在已登录设备签发、60 秒、一次性；链接格式与登录页识别同源（`portal/entry-links.ts` 的 `quickLoginLink`），倒计时按响应的 `expires_in` 走，不受本机时钟偏差影响。
- 改密码时当前密码错回 401：请求带 `passwordCheck`，错误落到「当前密码」框，不能当作会话失效登出；本地预检与后端 `crypto.ValidatePassword` 同规则（≥ 8 字符、≤ 256 字节、字母与数字）。
- 会话位置与 IP 按 D-F-3 不显示，设备名由 `user_agent` 推出；只列门户会话，当前会话置顶、不能下线；下线照设计直接执行、不弹确认。
- 个人信息不显示「用户组」（`GET v1/me` 没有），用户 ID 显示 uuid 前 8 位（与后台一致，设计稿的数字编号后端没有）。
- Telegram 卡文案照设计稿：未绑定「绑定后，到期、流量和工单回复的提醒也能发到 Telegram。」+「绑定 Telegram」，出码后「我已发送，完成绑定」；已绑定「已绑定 @x。到期、流量、工单回复等提醒可以发到 Telegram。」+ 红字「解除绑定」（保留确认框，设计稿没有，安全项）。通知卡标题「通知方式」。
- Telegram 绑定指令是 `/start CODE`（设计稿的 `/bind` 会绑定失败），另给 `t.me` 深链；展示绑定码期间 3 秒轮询绑定状态。
- 通知偏好按后端 3 类 × 2 渠道（设计稿的五个事件合并成类），交易类锁定开启；每次点击 PUT 一项，乐观更新、失败回滚。
- 本页写操作都没挂幂等中间件，不带幂等键。
- Telegram 卡的讨论群入口只看 `GET v1/me/telegram` 的 `discuss_link`（恒在，null 不显示），只渲染 https 链接；入群审核开没开门户不知道，文案只说「可能需要」。
