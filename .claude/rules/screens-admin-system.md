# 后台 · 通知与插件

- 邮件设置的 SMTP 六字段每次整体覆盖：「注册与验证」卡保存时必须带「已保存」的 SMTP 字段（不是 SMTP 卡里没保存的输入），密码不带。
- Webhook 钩子按 code upsert、省略的字段写成零值：新建时生成避开现有 code 的 code（撞上会静默覆盖），编辑与启停都从现有行回填全字段（`logic.ts` 的请求体构建）。
- 钩子超时（500–30000 毫秒）与重试次数（1–10）后端只有 DB CHECK，越界变 500，前端先拦。
- 三个测试发送用的都是已保存的配置：渠道卡有未保存修改时禁用测试按钮。
- Telegram 扩展设置（`/v1/settings/telegram/extras`）与 Telegram 主设置是两个接口：主设置的保存会改启用开关与 webhook，扩展每次整份提交 7 个键。10-16 起扩展的 5 个键在 Telegram 卡弹窗（`TelegramCard.tsx` 的 `TelegramDialog`）的「机器人与群组」一节，弹窗保存时按各自是否改动分别提交；两个管理员提醒开关（收款、工单，保持两个不拆三项）在页面「管理员提醒」一节即时保存（`adminAlertBody`，其余 5 键照已保存值）。管理员群组 chat id 是测试消息的默认目标，也是收款、工单提醒的去处。管理员群组与用户群的 chat id 只收负数（`parseGroupChatId`）；测试消息的目标可以是私聊（正数，`parseChatId`）。
- 产品取舍：设计稿里的「重置密码」「礼品卡兑换成功」模板后端没有，按后端现有模板显示；钩子事件只用后端返回的目录，不提供 `ticket.replied` / `node.offline` / `node.online`。
- 10-16 设计稿：通知渠道页是「发送渠道」三张卡（站内信始终开启、不可配置；邮件；Telegram）+「管理员提醒」+「注册与验证」卡，配置都在弹窗里；弹窗一直挂载，关掉不丢草稿，卡上显示「未保存」。
- 邮件模板是渠道筛选 + 表格（模板 / 标识 / 状态），点行开 720 宽弹窗；没有「放弃修改」。保存、恢复默认、发测试与改 SMTP 一样要近期重认证（用户 10-21 定；403 `reauth_required` 由外框的重认证框接住后重放），预览不要。设计稿非邮件渠道不显示主题，但后端所有渠道都要求主题 1–200 字，所以主题对所有渠道都显示。
- 钩子用弹窗新建，投递记录有表头（时间 / 事件 / 响应 / 耗时 / 次数）；页面不提供测试投递（后端接口仍在），不显示成功率与排队数；行内健康字样按 `hookHealth`（近 7 天失败数）。
- av4（样稿 admin-v4）：通知渠道三节 `SectionTitle variant="group"`；发送渠道与注册行是 `Card flush` + `RowList`，右侧「配置」按钮打开弹窗（行本身不可点）；注册行写全「…注册 · 需验证邮箱 / 不验证邮箱」（页面与注册弹窗两处）。管理员提醒是开关行卡片。邮件模板表 `Table boxed`；「新建钩子」在页头 `PageActions`，钩子列表 `RowList`（`StatusDot` 状态点、端点 mono、事件、开关与「投递记录 / 编辑 / 删除」），投递记录展开在行下方（`role="listitem"` 的块，与 Row 同级）；编辑弹窗与删除确认框挂在列表外（`HooksTab` 持有状态），`RowList` 里只放 listitem。
