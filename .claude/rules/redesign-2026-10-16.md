# 10-16 设计稿还原与套餐改造（跨模块口径）

用户 2026-10-16 重画了后台（设计稿 `面板.zip`，用户端这次没改）。下面的口径压过各模块规则文件里的旧说法；各块改到哪个模块，就同步改写那个模块的规则文件。全量计划在 `.claude/redesign-plan.md`。

## 还原口径
- 后台页面按设计稿**显示出来的效果**还原；设计稿脚本里有、页面上不可达的假数据和逻辑不算。
- 设计稿没显示的功能，前后端一起删（清单见计划「删除清单」），**但安全项保留**：敏感操作前的二次认证、调整余额的确认框、取消订单 / 封禁 / 重置时必须填原因、「别人刚改过，请载入最新」的冲突提示、加载中 / 出错 / 空状态、键盘操作。
- 界面文案里「门户」一律改称「用户端」；代码、注释、规则里仍可叫门户（portal）。
- 页面级说明放进页签栏右侧的「?」帮助（`PAGE_HELP`），不写在页面里；字段旁的就地提示不受此限。
- 设计稿里的 Surge 订阅、「到期自动续费」是笔误：系统没有这两样。

## 套餐
- 只有两类：**订阅套餐按时间算**（月 / 季 / 半年 / 年四档价，每周期一份流量、新周期清零，到期由用户自己续费）；**一次性套餐按流量算**（一个价格 + 一份总流量，不清零、用完即止；有效天数可选，空为永久；不能续费）。
- 挂在套餐下面的：流量重置（开关、每次价格、次数上限：订阅按每周期，一次性按有效期内）、用量（流量、设备、限速）、线路（节点池，按套餐绑定，**改动立即生效**）、销售（可见范围、新购、续费〔仅订阅〕、变更、推荐）、版本（改用量走草稿 → 发布；订阅老用户下周期切换，一次性老用户不受影响）。
- 归档后老用户**不能续费**，已有订阅到期结束。
- 没有：流量包（商品、页签、订单类型 addon、未分配余量、加流量包按钮全删）、美元价、用户组专属价、价格时间窗、自定义周期、卖点、上下架时间窗、排序、库存、每人限购、会员折扣、券的限定时长。
- 落点由用户选：一次性再买同一个 → 叠加（总量加上、天数顺延）或新开；订阅与一次性之间 → 换掉或新开。跨类型换掉的抵扣：订阅按剩余时间比例，一次性按剩余流量比例（有天数时再按剩余天数算，取较小），抵扣在报价里列出。
- 送的流量（礼品卡、后台「加流量」、盲盒奖品）当期有效：加到本周期上限，周期结束作废；一次性套餐直接加到总量上。
- 礼品卡套餐卡：送订阅套餐要选一档周期价；一次性只有一个价。
- 试用保留「试用套餐 + 试用时长（小时）」。

## 钱
- **整个系统只有人民币**：美元与「币种」这一维全删（价格、余额、账本、充值、券、佣金、支付、报表、总览切换）。只有调第三方支付接口时传一个固定的 CNY。

## 不新做后端能力（用户 10-16 收窄）
设计稿画了、但现有后端没有的东西，**只做这 5 样**：
1. ⌘K 直接搜用户、订单、节点（三个列表接口已支持 `q`，纯前端）。
2. 协议表单的中文名、按条件显示、默认值、高级参数折叠（元数据放后端协议定义，前端不写死字段）。
3. 订单显示具体支付方式（支付记录已存 method，只是没返回）。
4. 提现按「处理中 / 已完成 / 全部」筛选（接口多收状态）。
5. 近 7 天登录 IP 数（用画像里现有的 ips[].last 在前端算）。

其余一律不做，页面按现有能力显示：路由匹配类型用现有的；不写路由 DNS；节点身份那一栏显示证书指纹，不做单节点令牌与重签；节点概览用现有带宽曲线；订阅模板只读列出「客户端 → 格式」，没有「设为默认」；订阅域名不显示健康状态；实时事件只做前端（每条未读、全部已读、按现有事件类型分页签，不跨刷新保存）；用户列表不排序、页脚只显示现有总数；风控成员不显示最近出现；券批量上限、盲盒建模板就填奖品、管理员提醒两个开关、知识库筛选不带计数、待处理到账与支付渠道的统计都保持现状。

## 保留（设计稿没画也不删）
- Telegram 扩展（/sub、/start 欢迎语、入群审核、用户群、讨论群）：放进「通知渠道 › Telegram」卡的配置弹窗里。
- 节点池（新建节点必填）与池的状态、路由兜底规则、服务器的退役与删除：设计稿的帮助或提示里引用了它们。
