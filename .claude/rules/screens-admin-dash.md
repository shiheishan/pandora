# 后台 · 仪表盘

- 版式（10-16 设计稿）：分区「待办 → 经营 → 运行」。待办 = 最紧急的一项放大（左）+ 其余各项列表（右），全为 0 时一条「没有待处理的事」；经营 = 今日概况三格（今日收入、有效订阅、近 24 小时流量）+ 每日净收入曲线（7 / 30 / 90 天）+ 新用户与日活曲线（近 14 天）；运行 = 流量排行 + 服务健康。
- 只有人民币：概览的 `revenue` 是单个对象，`GET v1/revenue/timeseries` 只收 `days`，待办里待审提现是单个 `amount`；没有币种切换。
- 仪表盘登录即可进，没有自己的数据：每张卡各自发请求、各自画，各自加载、各自失败、各自重试，一张卡坏了不能牵连别的卡。新增卡片照此办。
- 每张图 / 列表有自己的空状态（「还没有收入 / 用户 / 流量」）并带一个去配置的链接（套餐、注册与邀请、节点）。
- 「待办」和侧栏徽标共用 `src/admin/tasks.ts` 的同一条 `GET v1/dashboard/tasks` 查询与 schema，不在本目录另起。
- 流量与积压三个接口的字节一律是十进制字符串（numeric 聚合，可能超过 2^53），不是 JSON number；排行的占比、均值、差值用 BigInt 算（`rank.ts`）。
- 流量排行取近 24 小时前 10 名：每行占全部的百分比（节点按 reported、用户按 attributed）、与当前列表均值的差、朱红均值竖线；按流量 / 上行占比 / 名称三种排序；底部 Σ 合计行；「数据说明」气泡列出未归属与无效条目。
- 服务健康：状态行 + 有降级时的告警块 +「需要关注」「运行正常」两组 + 刷新按钮（重新请求 `GET v1/system/status`）；备份行点开备份抽屉。
- 分层：数据到卡片、行、文案的映射全部放纯函数（`model.ts` 待办 / KPI / 服务健康，`chart.ts` 两张曲线，`rank.ts` 流量排行，都有单测），组件只负责摆放；共用小件（分区标题、卡片标题条、文字页签、卡内空 / 错 / 骨架）在 `parts.tsx`。
- 图表手写 SVG（平滑曲线），不引图表库；悬停与方向键逐点查看数值；动态 style 只用于条宽、坐标百分比。
- 格式化（字节、计数、金额、时间）一律取 `core/format.ts`。
- 用户流量排行只显示脱敏邮箱（`email_masked`）。
- 页面说明放 `admin/page-help.ts` 的 `PAGE_HELP['dash']`，不写在页面里。
