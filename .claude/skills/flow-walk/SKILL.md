# 像用户一样走一遍流程

目标：改完页面后，证明「在浏览器里点得通」，不是「测试绿了」。每一步有页面上的文字或截图作证据。

和别的验证的分工：

| 要证明什么 | 用什么 |
|---|---|
| 代码对不对、CI 绿不绿 | verify |
| 接口在真库上的行为 | `panel/tests/*.sh`（CI 冒烟栈上跑） |
| 页面拿真数据不崩 | `panel/frontend/tests/smoke/`（CI） |
| 订阅文件能渲染、能连 | subscription-e2e |
| 打开快不快 | web-perf |
| **用户在页面上点得通，文字和结果对** | **本 skill** |

## 先选环境

| | 假后端（本机） | 测试机真后端 |
|---|---|---|
| 起法 | `bash .claude/skills/flow-walk/scripts/mock-up.sh up` | 按 panel-install 装好的面板，别名与后台前缀看 `~/ai/servers/README.md` 和 `ops-local/` |
| 速度 | 秒级起，状态在内存，重启复原 | 数据真实，状态累积 |
| 能验 | 页面交互、文案、表单校验、错误态；页面按契约走通 | 真实数据流：下单入账、佣金、订阅文件、节点接入、权限 |
| 不能验 | 后端逻辑、真支付、真节点、邮件 | 破坏性场景（空/错/慢）造不出来 |
| 账号 | 门户 `user@pandora.dev`，后台 `admin@pandora.dev`（另有只读 `viewer@pandora.dev`），口令见 `panel/frontend/dev/mock-api.ts` 的 `MOCK_ACCOUNTS` | 管理员由 `aegis-adminctl create` 建（panel-install 交接）；口令在 1Password，不读 `ops-local/**/secrets/` |

怎么选：
- 改的是页面布局、文案、表单、前端状态：只跑假后端。
- 改的是接口、金额、履约、权限，或要出验收结论：假后端过一遍，再在测试机上过一遍。
- 假后端上的「通」只证明页面符合契约。钱和订阅的对错以测试机为准。
- 测试机只有一台时，**压测、复测期间不要跑**（先和总协调确认），登录和下单会混进压测的数据与限流里。

### 假后端

- 命令（从仓库根执行）：`mock-up.sh up [前端目录]`、`down`、`status`。
  - 起 `npm run dev:portal`（127.0.0.1:5181）和 `npm run dev:admin`（127.0.0.1:5182），端口写死并加 `--strictPort`，被占就报错，不换端口、不抢。
  - 避开 8766（别的任务的原型服务器）。
  - 要测 worktree 就传它的 `panel/frontend`；没有 `node_modules` 先在那里 `npm ci`（期间别跑 go 命令，见根 CLAUDE.md）。
  - 用完 `mock-up.sh down`。
- 内置浏览器优先用 `preview_start`：`.claude/launch.json` 里已有 `portal-mock`（5181）和 `admin-mock`（5182）两条配置。每次 `preview_start` 会自动开一个标签并返回 `tabId`，那个标签就是自己的，用完 `tabs_close`，再 `preview_stop`。`launch.json` 别的任务在用，**不要自己改**。用 `preview_start` 就不要再跑 `mock-up.sh`（端口会冲突）；没有 `preview_start` 的环境才用 `mock-up.sh` 加 `navigate`。
- 设了 `PANDORA_API` 时假后端不挂，`/v1` 代理到真网关（规则见 `.claude/rules/frontend-mock.md`）；平时不设。
- 门户场景：`POST /v1/__mock/portal-scenario {"name": "..."}`，不需要令牌，切换即重建全部状态；场景名与含义见 `panel/frontend/src/portal/fixtures.ts` 的 `SCENARIOS`（default / empty / multi / legacy / error / slow）。
  - 在页面里切：`javascript_tool` 执行 `await fetch('/v1/__mock/portal-scenario',{method:'POST',headers:{'content-type':'application/json'},body:JSON.stringify({name:'empty'})})`，然后刷新。
  - 流程默认在 `default` 场景走，空态与错误态各挑一个场景补一遍。
- 后台写操作的重新认证：要走「验证身份后继续」流程，先 `POST /__mock/expire-reauth`（路径没有 `/v1`），再做写操作，弹框里输入假后端口令。
- 假收银台：门户下单选支付方式后，页面跳 `/v1/__mock/cashier?...`，点「模拟支付成功」回到门户；「模拟支付成功但回调丢失」用来看确认中状态。
- 注册：验证码固定 `123456`，也会显示在表单提示里。

### 测试机

- 面板怎么装、后台前缀、管理员账号：先读 `~/ai/servers/README.md` 找到那台，再读它目录下的 `AGENTS.md`，装机按 panel-install。仓库里不写任何 IP、域名、前缀。
- **登录由用户本人在浏览器里完成**（门户口令、后台口令、后台写操作弹出的重新认证口令都一样）。agent 不输入口令和令牌；用户说「已登录」后，在那个标签页上接着点。
- 支付：真支付渠道在测试机上通常没配。买套餐有三条路，走哪条由当次任务定：
  - 先在后台给用户调余额，结账页勾「使用余额抵扣」全额抵扣；
  - 后台人工开单选「赠送」或「线下已收款」；
  - 配了演示渠道时，走渠道自己的回调（参考 `panel/tests/epay_e2e.sh`）。
- 注册要邮件验证码：测试机没配邮件渠道就不测注册，用管理员建好的账号走登录，在记录里写明原因。
- 后台 IP 限流每分钟 240 次，反复刷页面和反复登录会撞上，别循环刷新（见 `rules/frontend-smoke.md`）。

## 操作方法

1. **自己开标签页，记下 tabId。** `tabs_create` 开一个，之后每个调用都显式带 `tabId`（窗格是共用的，同时开着两个标签时「当前标签」会在调用之间跳）；不碰别的任务开的标签。标签数到上限（`tabs_create` 报「Could not open a new tab」）时只关自己开过的（`preview_start` 自动开的也算），向总协调说明。用完 `tabs_close`，`mock-up.sh down` 停服务。
2. **两种尺寸都走。** 桌面用 `resize_window` `preset: "desktop"`，手机用 `preset: "mobile"`（375x812）。每条流程至少在桌面完整走一遍，手机上走关键几步（导航、表单、弹窗是否可点、有没有横向滚动）。测完把尺寸恢复成 `desktop`。切尺寸后刷新页面。
3. **读文字优先，截图只用来核对视觉**（布局错位、遮挡、截断、颜色与状态标签、深浅色主题、手机宽度）。点击优先 `ref`，断言用 `read_page` / `find` / `get_page_text`，表单用 `form_input`。
   - 窗格没显示时（用户没打开 Browser 面板），新标签的视口是 0x0，`read_page` 返回空，截图超时。先对该标签 `resize_window`（例如 1280x900）再读；要截图就得请用户把窗格打开，否则这一项记「未测」。
4. **写操作要核对两层。**
   - 页面层：toast 文字、列表里的新行、状态标签。
   - 接口层（需要时）：`read_network_requests` 找对应请求，看状态码和响应体；`read_console_messages` 看有没有报错。
   - 本表「要核对的结果」一列写的是页面文字，接口层只在标了「接口」的步骤看。
5. **每步记一行**，不攒到最后补（格式见下）。失败不重试到绿：记下实际表现，截图，停下报告。
6. **别在已有数据上做不可逆的事。** 测试机上只动自己建的测试用户和订单；删除、取消订单类操作只对自己下的单做。

### 记录格式

一张表，一步一行：

| 流程 | 步骤 | 期望 | 实际 | 截图 | 结论 |
|---|---|---|---|---|---|
| 门户·买套餐 | 3 提交订单 | 弹出支付方式选择 | 同期望 | 无 | 通过 |
| 门户·换套餐 | 2 看报价 | 出现「剩余天数折算」一行 | 一直显示「计算中…」 | shots/change-2.png | 失败 |

- 期望写页面上会出现的字，不写「正常」。
- 实际写看到的原文；一致就写「同期望」。
- 截图只有失败和视觉核对才有路径，截图放会话 scratchpad，不进仓库。
- 结论三选一：通过 / 失败 / 未测（写原因）。
- 收尾给一行总结：环境（假后端 / 测试机别名）、提交号、桌面与手机是否都走了、失败几条。

## 门户流程

入口 `http://127.0.0.1:5181/`（假后端）或测试机站点根。路由是 hash：`/#/<页面>`，页面有 overview、subs、plans、checkout、orders、wallet、referral、tickets、messages、help、account。以下按 `default` 场景写。表里只写「核对哪一类结果」，按钮名、toast、预览行的原文以页面当前文案为准，记录表里抄页面上看到的原文；文案对不上先怀疑本表过时，不要直接判失败。

| 流程 | 起点 | 步骤 | 要核对的结果 |
|---|---|---|---|
| 登录 | `/#/`（未登录） | 填账号登录 | 进到概览，顶部导航出现；错口令有错误提示且不跳转 |
| 注册 | 同上，切注册 | 填邮箱（需邀请码时填邀请码）取验证码；填验证码和密码（至少 8 位含字母和数字）提交 | 步骤条从第 1 步走到第 2 步；成功有提示并进入概览。假后端验证码 `123456`；测试机无邮件渠道则标未测 |
| 买套餐（新购） | `/#/plans`，先切 `empty` 场景 | 选周期，点套餐卡的选择按钮；结账页确认周期，选支付方式（默认第一个；POST 渠道的页面应按「暂不可用」处理，别选），提交；跳到假收银台后点「模拟支付成功」 | 结账页订单预览有生效时机和应付金额；支付后回到订单详情（地址带 `?paid=1`），状态已支付并弹支付成功框；回概览，当前套餐是所买套餐，到期日约 30 天后，已用 0 B（实测：标准版月付 ¥29.00，概览显示标准版、200 GB） |
| 续费 | `/#/subs` | 点「续费」（或套餐页当前套餐的续费）；结账页提交并支付 | 预览说明新周期怎么接（未过期：接在原到期日之后；已过期：从付款时起算，原订阅地址自动恢复）；支付后到期日往后推，订阅地址不变 |
| 换套餐看报价 | `/#/plans`（`default` 有「专业版」） | 点别的套餐的换套餐按钮；停在结账页看预览，不付款；再换周期、再输优惠码 | 标题注明订阅地址不变；预览有剩余天数折算和新周期；降级时有差额退回余额的说明；报价算出来前应付显示骨架而不是 0；不支持变更的套餐按钮置灰。**接口**：`POST …/change-plan/preview` 返回 `direction`、`proration_credit`、`total`，与页面数字一致 |
| 加流量包 | `/#/plans?tab=packs`（页面上点流量包标签） | 点一个容量卡的购买；结账页看预览；提交并支付 | 预览写明有效期与使用顺序（订阅流量用完后才用流量包）；支付后 `/#/subs` 用量卡里流量包剩余增加；没有生效订阅时的提示记原文 |
| 导入到客户端 | `/#/subs` | 看一键导入卡；点各客户端一行的导入；点 v2rayN 的复制 | 导入行有深链（`clash://…`，用 `read_page` 看 href，不用真唤起）；点后有 toast；可用节点卡列出节点名、协议、倍率 |
| 兑换卡 | `/#/wallet` | 输入卡密，先查询再兑换 | 查询后显示卡面内容；兑换后账户余额增加（实测 ¥26.50 变 ¥126.50）、我的礼品卡多一行、余额明细多一行、卡面收起。点完等约 1 秒再读。假后端卡密：`GC-0923-H2K9-7QPA`（余额 ¥100）、`GC-1001-TRAF-0200`（200 GB 流量）、`GC-EXTD-0007-DAYS`（顺延 7 天）、`GC-0000-NEWU-0001`（报仅限新用户）；重复兑换要报错。测试机的卡密由后台「营销 → 礼品卡」现发 |
| 重置链接 | `/#/subs` | 点更换订阅地址，弹窗确认 | 弹窗说明旧链接和已导入节点立即失效，并写明限频（两次间隔至少 10 分钟，每天最多 5 次）；成功后地址变成新的（点完立刻读可能还是旧地址，等 1 秒）；紧接着再换一次应被限频拒绝，toast 是后端原话（测试机上核对，假后端不模拟限频） |
| 钱包余额 | `/#/wallet` | 看账户余额；选充值金额，走支付；回来看余额明细 | 金额与概览、结账页的可用余额一致；充值成功后余额增加，明细多一行 |
| 订单 | `/#/orders` | 看待支付单的去支付；取消订单并确认 | 待支付单有待支付标签；取消后有提示，待支付块消失；已取消的单不能再支付 |
| 退出 | `/#/account` | 点退出登录 | 回登录页；`localStorage` 里门户令牌被清掉 |

购买模型改造（多订阅、自选抵扣）合并后，受影响页面逐条复核上表；对不上的先改上表，再走流程。还没有现成页面的流程写在这里，别提前编。

## 后台流程

入口 `http://127.0.0.1:5182/`（假后端）或测试机的 `<后台前缀>`。路由是 hash：`#/<模块>/<标签>`，如 `#/users/list`、`#/billing/orders`、`#/nodes/nodes`、`#/nodes/servers`。抽屉由路径带出：用户 `#/users/list/<用户id>`，节点 `#/nodes/nodes/<节点id>/<标签>`（标签有 `metrics`、`proto`、`routing`、`identity`、`ops`）。写操作会弹「验证身份后继续」，输入口令后原操作随后继续。表里同样只写核对哪类结果，文案以页面为准。

| 流程 | 起点 | 步骤 | 要核对的结果 |
|---|---|---|---|
| 登录 | `#/`（未登录） | 填后台账号登录 | 落到仪表盘，侧栏按权限显示模块；`viewer` 账号看不到写入口 |
| 开单·待用户支付 | `#/billing/orders` | 点人工开单，选用户、套餐与周期、结算方式「待用户支付」，填开单原因（至少 5 个字），创建 | toast 写明订单号和 30 分钟支付期限；订单列表出现待支付单；用该用户登录门户 `/#/orders` 能看到并支付 |
| 开单·线下已收款 | 同上 | 结算方式选线下已收款，填凭证号和开单原因，入账并开通 | toast 说明已入账、订阅已开通；订单已完成；用户订阅出现或顺延。**接口**：账本有一笔入账，收入与佣金计入（测试机上查） |
| 开单·赠送 | 同上 | 人工开单（地址变成 `?new=1`）；用户框输入邮箱或用户 ID 的一部分并在匹配列表里点中；选套餐与周期；结算方式选赠送（0 元）；填开单原因提交 | toast 说明已赠送开通；订单列表最上面多一行：带「人工」标记、金额 ¥0.00、状态已支付；自动打开订单抽屉，显示优惠、应付 ¥0.00、来源（人工开单）和开单原因；不计收入。用户已有别的套餐时，toast 改为在原订阅上换套餐、订阅链接不变，并说明退回余额的金额 |
| 换发链接 | `#/users/list`，点用户行开抽屉 | 点更换订阅地址，弹窗确认 | 弹窗里能看到「连节点密码一起换」的说明；成功 toast 提示让用户到门户重新复制；用该用户的门户核对：订阅页地址变了，旧地址不再可用（测试机上用 curl 拉旧地址应失败） |
| 加时长 | 同上 | 点加时长，选订阅与天数，确认延长 | toast 给出延长天数和新到期；抽屉里到期时间变化，流量配额一起往后推，已用流量不清零；已过期订阅走「确认救回并延长」 |
| 加流量包 | 同上 | 点加流量包，选订阅与容量，确认发放 | toast 给出流量包剩余合计；用户门户用量卡里流量包剩余同步增加 |
| 重置流量 | 同上，抽屉「流量重置」标签；或 `#/users/resets` 顶部 | 点立即重置本期，或在列表页输入邮箱点手动重置；填重置原因（5 到 500 字）并确认 | 成功 toast 写明清零量；重置历史多一行，门户该订阅本期已用归零。试用订阅与无生效订阅的用户，按钮置灰或报 422 原话 |
| 建节点拿接入命令 | `#/nodes/nodes` | 点新建节点，按表单填名称、协议、服务器等，保存；再开该节点抽屉的「身份与令牌」标签，签发一键安装令牌 | 建好后提示节点是草稿，签发令牌并启用后才会下发；签发后出现命令和令牌两行，提示仅显示一次和有效期（30 分钟）；刷新后令牌不再显示，抽屉里多一行待用安装令牌 |
| 加服务器拿接入命令 | `#/nodes/servers` | 点添加服务器，填名称，提交 | toast 说明已添加为草稿、正在签发安装令牌；页面出现安装命令区域 |

注意：
- 命令与令牌是密钥，**不要抄进记录表或报告**，只记「出现了命令和令牌两行」。
- 真节点接入（用命令在机器上装 pdnd）和协议逐个验证不在本 skill 内，见 node-e2e skill；测试机见 test-machine。
- 假后端建的节点没有真机，不会上线。

## 坑

- **SSE 让网络永远不空闲**：页面开着实时事件长连接，不要等「网络空闲」。导航后等页面的 `load`，再固定等 1 到 2 秒，或直接等某个文字出现（`find`）。只差 `#路由` 的 `navigate` 是同文档跳转，不重新加载、渲染晚 1 到 2 秒：要验「刷新后还在」就显式刷新，马上 `find` 找不到先 `wait` 2 秒。
- **令牌存储键**：`localStorage` 里门户是 `pandora-portal-token`，后台是 `pandora-admin-token`（`panel/frontend/src/core/token.ts` 的 `tokenStorageKey`，web-perf 的脚本也用它）。
  - 同源的两个入口键不同、互不通用。
  - 验退出、验令牌被清、验登录态是否保持时看它；不要把令牌值贴进记录表。
  - 存储被禁用时令牌只留在内存，刷新后要重新登录，这是设计行为。
- **假后端状态在内存**：vite 重启即复原，每次验收从干净状态开始比较稳；写操作做完想重来就重启（`mock-up.sh down` 再 `up`）。
- **后台主题互通**：两个 vite 进程经 `node_modules/.cache/pandora-mock/appearance.json` 共享生效主题，后台启动时会重写它；先起后台再看门户外观，别被上次激活的主题误导。
- **弹窗里的按钮在 `<dialog>` 里**：`read_page` 能读到，但页面背景被遮；点完弹窗再读背景页的文字。
- **toast 很快消失，而且不在 `<main>` 里**：`get_page_text` 只读 `<main>`，读不到 toast。toast 住在 `[role=status]` 里。要核对文字，用 `javascript_tool` 在同一段脚本里点按钮并每 200 毫秒读一次 `document.querySelector('[role=status]')?.textContent`，收集到的去重后记录；点按钮用 `[...document.querySelectorAll('button')].find(b => b.textContent.trim() === '…').click()`。
- **支付页是整页跳转**：假收银台会离开门户再回来，tabId 不变，等回到 `/#/…` 再核对；订单状态可能还在「确认中」，等 3 到 6 秒再读。
- 记录表、截图和报告里的测试机一律写别名或 `<后台前缀>`（仓库公开红线见根 CLAUDE.md）。
