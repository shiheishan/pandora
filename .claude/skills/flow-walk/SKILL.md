# 像用户一样走一遍流程

目标：改完页面后，证明「在浏览器里点得通」，不是「测试绿了」。每一步有页面上的文字或截图作证据。

和别的验证的分工：

| 要证明什么 | 用什么 |
|---|---|
| 代码对不对、CI 绿不绿 | verify |
| 接口在真库上的行为 | `panel/tests/*.sh`（CI 冒烟栈上跑） |
| 页面拿真数据不崩 | `panel/frontend/tests/smoke/`（CI） |
| 订阅文件能渲染、能连 | subscription-e2e |
| 打开快不快 | web-perf |
| **用户在页面上点得通，文字和结果对** | **本 skill** |

## 先选环境

| | 假后端（本机） | 测试机真后端 |
|---|---|---|
| 起法 | `bash .claude/skills/flow-walk/scripts/mock-up.sh up` | 按 panel-install 装好的面板，别名与后台前缀看 `~/ai/servers/README.md` 和 `ops-local/` |
| 速度 | 秒级起，状态在内存，重启复原 | 数据真实，状态累积 |
| 能验 | 页面交互、文案、表单校验、错误态；页面按契约走通 | 真实数据流：下单入账、佣金、订阅文件、节点接入、权限 |
| 不能验 | 后端逻辑、真支付、真节点、邮件 | 破坏性场景（空/错/慢）造不出来 |
| 账号 | 门户 `user@pandora.dev`，后台 `admin@pandora.dev`（另有只读 `viewer@pandora.dev`），口令见 `panel/frontend/dev/mock-api.ts` 的 `MOCK_ACCOUNTS` | 管理员由 `aegis-adminctl create` 建（panel-install 交接）；口令在 1Password，不读 `ops-local/**/secrets/` |

怎么选：
- 改的是页面布局、文案、表单、前端状态：只跑假后端。
- 改的是接口、金额、履约、权限，或要出验收结论：假后端过一遍，再在测试机上过一遍。
- 假后端上的「通」只证明页面符合契约。钱和订阅的对错以测试机为准。
- 测试机只有一台时，**压测、复测期间不要跑**（先和总协调确认），登录和下单会混进压测的数据与限流里。

### 假后端

- 命令（从仓库根执行）：`mock-up.sh up [前端目录]`、`down`、`status`。
  - 起 `npm run dev:portal`（127.0.0.1:5181）和 `npm run dev:admin`（127.0.0.1:5182），端口写死并加 `--strictPort`，被占就报错，不换端口、不抢。
  - 避开 8766（别的任务的原型服务器）。
  - 要测 worktree 就传它的 `panel/frontend`；没有 `node_modules` 先在那里 `npm ci`，期间别跑 go 命令。
  - 用完 `mock-up.sh down`。
- 内置浏览器优先用 `preview_start`：`.claude/launch.json` 里已有 `portal-mock`（5181）和 `admin-mock`（5182）两条配置。每次 `preview_start` 会自动开一个标签并返回 `tabId`，那个标签就是自己的，用完 `tabs_close`，再 `preview_stop`。`launch.json` 别的任务在用，**不要自己改**。用 `preview_start` 就不要再跑 `mock-up.sh`（端口会冲突）；没有 `preview_start` 的环境才用 `mock-up.sh` 加 `navigate`。
- 设了 `PANDORA_API` 时假后端不挂，`/v1` 代理到真网关：想用本机前端对测试机时才这么用，平时不设。
- 门户场景：`POST /v1/__mock/portal-scenario {"name": "..."}`，不需要令牌，切换即重建全部状态。
  - 可选 `default`（一条生效的「专业版」订阅、一张待支付单、流量包、公告）、`empty`（什么都没有）、`multi`（两条订阅，第二条待续费）、`legacy`（Go 的 omitempty 字段全缺席）、`error`（读接口 500）、`slow`（读接口慢 2.5 秒）。
  - 在页面里切：`javascript_tool` 执行 `await fetch('/v1/__mock/portal-scenario',{method:'POST',headers:{'content-type':'application/json'},body:JSON.stringify({name:'empty'})})`，然后刷新。
  - 流程默认在 `default` 场景走，空态与错误态各挑一个场景补一遍。
- 后台写操作要重新认证，但登录后 15 分钟内不会弹（实测开单直接成功）。要走「验证身份后继续」流程，先 `POST /__mock/expire-reauth`（路径没有 `/v1`），再做写操作，弹框里输入假后端口令。
- 假收银台：门户下单选支付方式后，页面跳 `/v1/__mock/cashier?...`，点「模拟支付成功」回到门户；「模拟支付成功但回调丢失」用来看确认中状态。
- 注册：验证码固定 `123456`，也会显示在表单提示「开发模式验证码」里。

### 测试机

- 面板怎么装、后台前缀、管理员账号：先读 `~/ai/servers/README.md` 找到那台，再读它目录下的 `AGENTS.md`，装机按 panel-install。仓库里不写任何 IP、域名、前缀。
- **登录由用户本人在浏览器里完成**（门户口令、后台口令、后台写操作弹出的重新认证口令都一样）。agent 不输入口令和令牌；用户说「已登录」后，在那个标签页上接着点。
- 支付：真支付渠道在测试机上通常没配。买套餐有三条路，走哪条由当次任务定：
  - 先在后台给用户调余额，结账页勾「使用余额抵扣」全额抵扣；
  - 后台人工开单选「赠送」或「线下已收款」；
  - 配了演示渠道时，走渠道自己的回调（参考 `panel/tests/epay_e2e.sh`）。
- 注册要邮件验证码：测试机没配邮件渠道就不测注册，用管理员建好的账号走登录，在记录里写明原因。
- 后台 IP 限流每分钟 240 次（见 frontend-smoke 规则）。反复刷页面和反复登录会撞上，慢一点点，别循环刷新。

## 操作方法

1. **自己开标签页，记下 tabId。**
   - `tabs_create` 开一个，之后每个调用都显式带 `tabId`，不碰别的任务开的标签（浏览器窗格是共用的）。
   - 开不出新标签（`tabs_create` 报「Could not open a new tab」）说明窗格里标签数到上限：只关自己开过的，别人的不关，向总协调说明。
   - 用完 `tabs_close` 关掉自己的，`mock-up.sh down` 停服务。
2. **两种尺寸都走。** 桌面用 `resize_window` `preset: "desktop"`，手机用 `preset: "mobile"`（375x812）。每条流程至少在桌面完整走一遍，手机上走关键几步（导航、表单、弹窗是否可点、有没有横向滚动）。测完把尺寸恢复成 `desktop`。切尺寸后刷新页面。
3. **读文字优先，截图只用来核对视觉。**
   - 窗格没显示时（用户没打开 Browser 面板），新标签的视口是 0x0，`read_page` 返回空，截图直接超时报「Browser pane is not displayed」。先对该标签 `resize_window`（例如 1280x900）再读；要截图就得请用户把窗格打开，否则这一项记「未测」。
   - 断言用 `read_page`（带 ref，可点）、`find`（按文字找按钮）、`get_page_text`。
   - 截图只在这几种时候用：布局错位、遮挡、截断、颜色与状态标签、深浅色主题、手机宽度。
   - 点击优先 `ref`，不靠坐标。表单用 `form_input`。
4. **写操作要核对两层。**
   - 页面层：toast 文字、列表里的新行、状态标签。
   - 接口层（需要时）：`read_network_requests` 找对应请求，看状态码和响应体；`read_console_messages` 看有没有报错。
   - 本表「要核对的结果」一列写的是页面文字，接口层只在标了「接口」的步骤看。
5. **每步记一行**，不攒到最后补（格式见下）。失败不重试到绿：记下实际表现，截图，停下报告。
6. **别在已有数据上做不可逆的事。** 测试机上只动自己建的测试用户和订单；删除、取消订单类操作只对自己下的单做。

### 记录格式

一张表，一步一行：

| 流程 | 步骤 | 期望 | 实际 | 截图 | 结论 |
|---|---|---|---|---|---|
| 门户·买套餐 | 3 提交订单 | 弹出支付方式选择 | 同期望 | 无 | 通过 |
| 门户·换套餐 | 2 看报价 | 出现「剩余天数折算」一行 | 一直显示「计算中…」 | shots/change-2.png | 失败 |

- 期望写页面上会出现的字，不写「正常」。
- 实际写看到的原文；一致就写「同期望」。
- 截图只有失败和视觉核对才有路径，截图放会话 scratchpad，不进仓库。
- 结论三选一：通过 / 失败 / 未测（写原因）。
- 收尾给一行总结：环境（假后端 / 测试机别名）、提交号、桌面与手机是否都走了、失败几条。

## 门户流程

入口 `http://127.0.0.1:5181/`（假后端）或测试机站点根。路由是 hash：`/#/<页面>`，页面有 overview、subs、plans、checkout、orders、wallet、referral、tickets、messages、help、account。以下按 `default` 场景写；文字来自当前代码。

| 流程 | 起点 | 步骤 | 要核对的结果 |
|---|---|---|---|
| 登录 | `/#/`（未登录） | 邮箱、密码填账号，点「登录」 | 进到概览，顶部有导航「概览 我的订阅 选购套餐 订单」；错口令显示「邮箱或密码不正确」，不跳转 |
| 注册 | 同上，切「注册」 | 填邮箱（需邀请码时填邀请码），点「发送验证码」或「下一步」；填验证码和密码（至少 8 位含字母和数字），点「完成注册」 | 步骤条从「1 邮箱与邀请码」走到「2 验证与密码」；成功后 toast「注册成功，欢迎使用」并进入概览。假后端验证码 `123456`。测试机无邮件渠道则标未测 |
| 买套餐（新购） | `/#/plans`，先切 `empty` 场景 | 在「订阅套餐」选周期，点套餐卡的「选择<套餐名>」；结账页确认周期，在「支付方式」选一种（默认第一个「支付宝」；「QQ 钱包」是 POST 渠道，页面应按「暂不可用」处理，别选），点「提交订单并支付」；自动跳到假收银台（标题「假收银台」，显示订单号和金额），点「模拟支付成功」 | 结账页「订单预览」有「生效：支付后立即开通」和「应付」金额；支付后回到 `/#/orders/<订单id>?paid=1`，订单详情状态「已支付」，同时弹「支付成功」框，文字「已开通，有效期至 …」；点「完成」到概览，概览「当前套餐」是所买套餐，到期日约 30 天后，「已用 0 B」（实测：标准版月付 ¥29.00，概览显示标准版、200 GB） |
| 续费 | `/#/subs` | 点右上「续费」（或套餐页当前套餐的「续费」）；结账页提交并支付 | 结账页预览「新周期：接在原到期日之后，本期剩余流量照常可用」；支付后订阅到期日往后推，订阅地址不变。已过期订阅预览是「从付款时起算，原订阅地址自动恢复」 |
| 换套餐看报价 | `/#/plans`（`default` 场景有「专业版」） | 点别的套餐的「换成<套餐名>」；停在结账页看预览，不付款；再换一个周期、再输一个优惠码 | 标题下有「从专业版变更，订阅地址不变」；预览有「剩余天数折算」「新周期：今天起至 …」；降级时有「降级说明：差额退回余额，余额不可提现」和「差额退回余额」一行；报价算出来前「应付」显示骨架，不是 0。**接口**：`POST …/change-plan/preview` 返回 `direction`、`proration_credit`、`total`，与页面数字一致。「不支持变更」的套餐按钮置灰 |
| 加流量包 | `/#/plans?tab=packs`（页面上点「流量包」标签） | 点一个容量卡的「购买」；结账页看预览；提交并支付 | 预览有「有效期：立即生效，用完为止」「使用顺序：订阅流量用完后自动使用」；支付后 `/#/subs` 的用量卡里流量包剩余增加；没有生效订阅时的提示以页面为准，记原文 |
| 导入到客户端 | `/#/subs` | 看「一键导入」卡；点 Clash Verge 等一行的「导入」；点 v2rayN 的「复制」 | 导入行有深链（`clash://…`，用 `read_page` 看 href，不用真唤起）；点后 toast「正在唤起 …」；v2rayN 点后 toast「已复制订阅地址，在 v2rayN 里「添加订阅」粘贴即可」；「可用节点」卡列出节点名、协议、倍率 |
| 兑换卡 | `/#/wallet` | 「兑换礼品卡」输入卡密，点「查询」，再点「立即兑换」 | 查询后出现「礼品卡内容」「¥100.00 余额」「兑换后直接计入余额」；兑换后 toast「兑换成功：…」，「账户余额」增加（实测 ¥26.50 变 ¥126.50），「我的礼品卡」多一行 `GC-0923-H2K9…`，「余额明细」多一行「礼品卡 … +¥100.00」，查询出的卡面收起。点完等约 1 秒再读，页面更新有延迟。假后端卡密：`GC-0923-H2K9-7QPA`（余额 ¥100）、`GC-1001-TRAF-0200`（200 GB 流量）、`GC-EXTD-0007-DAYS`（顺延 7 天）、`GC-0000-NEWU-0001`（报「这张卡只能新用户使用」）；已兑换过的重复兑换要报错。测试机的卡密由后台「营销 → 礼品卡」现发 |
| 重置链接 | `/#/subs` | 点「更换订阅地址」；弹窗点「更换」 | 弹窗标题「更换订阅地址？」，正文含「旧链接和已导入的节点立即失效」与限频说明「两次更换至少间隔 10 分钟，每天最多 5 次」；成功 toast「订阅地址已更换」，上方地址变成新的（实测地址串整体变化；点完立刻读可能还是旧地址，等 1 秒）。紧接着再换一次应被限频拒绝，toast 里是后端原话（测试机上核对；假后端不模拟限频） |
| 钱包余额 | `/#/wallet` | 看「账户余额」；选充值金额，点「充值」，走支付；回来看「余额明细」 | 金额与概览、结账页「使用余额抵扣（可用 …）」一致；充值支付成功后余额增加，明细多一行 |
| 订单 | `/#/orders` | 看待支付单的「去支付」；点「取消订单」，弹窗「取消这笔订单？」再点「取消订单」 | 待支付单有「待支付」标签；取消后 toast「订单已取消」，待支付块消失；已取消的单不能再支付 |
| 退出 | `/#/account` | 点「退出登录」 | 回登录页；`localStorage` 里门户令牌被清掉 |

## 后台流程

入口 `http://127.0.0.1:5182/`（假后端）或测试机的 `<后台前缀>`。路由是 hash：`#/<模块>/<标签>`，如 `#/users/list`、`#/billing/orders`、`#/nodes/nodes`、`#/nodes/servers`。抽屉由路径带出：用户 `#/users/list/<用户id>`，节点 `#/nodes/nodes/<节点id>/<标签>`（标签有 `metrics`、`proto`、`routing`、`identity`、`ops`）。写操作会弹「验证身份后继续」，输入口令点「验证并继续」，原操作随后继续。

| 流程 | 起点 | 步骤 | 要核对的结果 |
|---|---|---|---|
| 登录 | `#/`（未登录） | 填后台账号登录 | 落到仪表盘，侧栏按权限显示模块；`viewer` 账号看不到写入口 |
| 开单·待用户支付 | `#/billing/orders` | 点「人工开单」，选用户、「套餐与周期」、结算方式「待用户支付」，填「开单原因」（至少 5 个字），点「创建订单」 | toast「订单 … 已创建，等待用户在 30 分钟内支付」；订单列表出现待支付单；用该用户登录门户 `/#/orders` 能看到并支付 |
| 开单·线下已收款 | 同上 | 结算方式选「线下已收款」，填「凭证号」和开单原因，点「入账并开通」 | toast「订单 … 已按线下收款入账，订阅已开通」；订单已完成；用户订阅出现或顺延。**接口**：账本有一笔入账，收入与佣金计入（测试机上查） |

## 坑

- **SSE 让网络永远不空闲**：页面开着实时事件长连接，不要等「网络空闲」。导航后等页面的 `load`，再固定等 1 到 2 秒，或直接等某个文字出现（`find`）。
- **令牌存储键**：`localStorage` 里门户是 `pandora-portal-token`，后台是 `pandora-admin-token`（`panel/frontend/src/core/token.ts` 的 `tokenStorageKey`，web-perf 的脚本也用它）。
  - 同源的两个入口键不同、互不通用。
  - 验退出、验令牌被清、验登录态是否保持时看它；不要把令牌值贴进记录表。
  - 存储被禁用时令牌只留在内存，刷新后要重新登录，这是设计行为。
- **只差 `#路由` 的跳转是同文档跳转**：不重新加载，页面不会刷新状态。要验「刷新后还在」就显式 `navigate` 到同一地址并刷新；要验换页就改 hash。
- **假后端状态在内存**：vite 重启即复原，每次验收从干净状态开始比较稳；写操作做完想重来就重启（`mock-up.sh down` 再 `up`）。
- **后台主题互通**：两个 vite 进程经 `node_modules/.cache/pandora-mock/appearance.json` 共享生效主题，后台启动时会重写它；先起后台再看门户外观，别被上次激活的主题误导。
- **弹窗里的按钮在 `<dialog>` 里**：`read_page` 能读到，但页面背景被遮；点完弹窗再读背景页的文字。
- **toast 很快消失，而且不在 `<main>` 里**：`get_page_text` 只读 `<main>`，读不到 toast。toast 住在 `[role=status]` 里。要核对文字，用 `javascript_tool` 在同一段脚本里点按钮并每 200 毫秒读一次 `document.querySelector('[role=status]')?.textContent`，收集到的去重后记录；点按钮用 `[...document.querySelectorAll('button')].find(b => b.textContent.trim() === '…').click()`。
- **支付页是整页跳转**：假收银台会离开门户再回来，tabId 不变，等回到 `/#/…` 再核对；订单状态可能还在「确认中」，等 3 到 6 秒再读。
- **内置浏览器标签数有上限**：窗格是共用的，满了 `tabs_create` 会失败。用完自己的标签要 `tabs_close`（`preview_start` 自动开的也算），别动别人的标签（例如 8766 原型服务器的）。每个调用都带 `tabId`，不依赖「当前标签」：同时开着两个标签时，工具返回的「当前标签」会在调用之间跳。
- **同文档 hash 跳转后要等**：`navigate` 到同一页面的另一个 `#/…` 后，页面渲染晚 1 到 2 秒，马上 `find` 会找不到，先 `wait` 2 秒。
- **go 命令与 `npm ci` 不并发**：`node_modules` 里的 flatted 带 Go 包，并发时 go 假失败。
- **仓库公开**：记录表、截图和报告里不写测试机 IP、域名、后台前缀，一律写别名或 `<后台前缀>`。
