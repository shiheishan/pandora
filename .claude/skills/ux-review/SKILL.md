# 体验审查与首次点击测试

用户的目标原话：

- 「用户在使用我们面板，每一步都很符合直觉，产生一种这个面板很好用的感觉」
- 购买：「希望用户可以按照自己的心愿购买套餐，并且能够快速了解，让他们产生一种：这个面板怎么这么好用的心理」

所以本 skill 只回答一个问题：**没看过说明的人，能不能一次点对，点完知道发生了什么、下一步做什么。**

| 要证明什么 | 用什么 |
|---|---|
| 页面点得通，文字和结果对 | flow-walk |
| 打开快不快（首屏、包大小、长任务的数字） | web-perf |
| **新手看得懂、一次点对、不犯错** | **本 skill** |

体感速度归这里，只看「点了有没有立刻的反馈」：按钮按下态或加载态、骨架而不是空白或 0、不跳版。毫秒数归 web-perf。

## 一、选环境与场景

只用本机假后端：要造「两份、余额只差 5 毛、已过期 3 天」这类局面，真后端造不出来。

- **原型阶段**（decision-research 第 6 步）：测 `.claude/purchase-proto/index.html`，地址带 `#s=<场景>&screen=<页>&clean=1`，`clean=1` 把测试栏整条藏起来。场景与 hint 在原型 `SCENARIOS`，流程与叫法在同目录 `flow.md`。
- **实现阶段**：测门户假后端。
  - 场景与 `proto-*` 的定义、两个切场景的接口见 `.claude/rules/frontend-mock.md`。
  - 给测试员的每个任务都用 `GET /v1/__mock/proto?s=proto-s2[&to=/plans]` 开头，等于「重来」；非原型场景用 `POST /v1/__mock/portal-scenario`，见 flow-walk「假后端」。
- **场景状态是整个 vite 进程共用的**：两个测试员连同一个端口，一个人付了款，另一个人的页面也跟着变。并行测试时一人一个端口，用 `scripts/mock-multi.sh`：
  - `up <前端目录> <个数>` 在 5191 起依次开门户实例（`--strictPort`，被占就报错）；
  - `down`、`status`。
  - 5181、5182 留给 flow-walk，8766 是原型服务器，都不占。
  - 起完后，总协调在内置浏览器里**逐个端口登录一次**（门户账号见 `dev/mock-api.ts` 的 `MOCK_ACCOUNTS`，令牌按源存 `localStorage`，端口不同就要分别登录）。测试员不登录、不碰口令；测「注册 / 登录 / 找回密码」的测试员拿一个没登录的端口。
  - vite 重启后会话失效，要重新登录。
- 后台：`npm run dev:admin`（flow-walk 的 `admin-mock`，5182），场景只有一份默认数据。

### 任务从哪来

任务按「用户想做成什么」写，**不写按钮上的字**：写「这个月流量快不够了」，不写「点加流量」。照着按钮名写任务，测出来的是找字能力，不是直觉。一次点对的路径只给总协调，不给测试员。

门户（场景以 `proto.ts` 为准，加场景时同步本表）：

| 场景 | 局面 | 任务 |
|---|---|---|
| proto-s1 | 一份标准版，流量只剩 8G | 这个月流量快不够了，让它够用；下个月还要接着用，先把钱交了；把它装到你现在这台手机上 |
| proto-s2 | 两份：「我的」流量快用完，「妈妈的 iPad」5 天后到期，余额 ¥8.50 | 只给你自己那份加流量；给你自己那份续一个月；再给自己另买一份分开用 |
| proto-s3 | 已有标准版，从选购页开始 | 延长现在用的；给家人另买一份标准版 |
| proto-s4 | 标准版还剩 25 天、用了 20G | 换成更大的套餐；换成便宜的，说出退了多少钱、退到哪 |
| proto-s5a | 只有一份，兑换页 | 朋友给了你一张卡（卡号见 `proto.ts` 注释，四张各测一次），用掉它 |
| proto-s5b | 两份，兑换页 | 用加 30 天卡给快到期的那份；用流量重置卡；用标准版月卡 |
| proto-s6 | 妈妈那份的链接 24 小时有 7 个地方在用 | 妈妈那份好像被人蹭了：只让她那份的旧链接失效，再给她的 iPad 装上新的，别影响你自己的 |
| proto-s7 / s7b / s7c | 余额 ¥12 / ¥50 / ¥29.50，续费 ¥30 | 续一个月，能用余额就用；说出最后用余额付了多少、另外付了多少 |
| proto-s7d | 余额 ¥0.20，用优惠码 LUCKY99 续费只要 ¥0.30（低于支付最低额） | 用优惠码 LUCKY99 续一个月；下不了单时，说出为什么、该怎么办 |
| proto-s8 | 标准版 3 天前过期 | 让它恢复能用，说出能用到哪天 |
| 未登录端口 | — | 用朋友给的邀请码 `PANDORA` 注册（验证码会显示在页面提示里）；忘了密码，找回来 |
| empty | 什么都没有 | 第一次买一个套餐，装到手机上 |
| default | 一份生效、一张待支付单 | 看看这个月花了多少钱、余额从哪来；有个问题想问客服 |

上面是 10-07 门户体验审查的用户任务清单（TASKS「门户体验审查」一条：注册登录、找回密码、选套餐、续费、另开一份、换套餐、流量包、添加到 App、换新链接、工单、余额与账单），落在了具体场景上。

后台另算：测试员扮「刚入职、没看过文档的客服」，任务如「用户说链接泄露了，帮他换」「给某用户补 7 天」「用户流量不够，送他一个流量包」「给某用户免费开一个月」「新加一台服务器，拿到安装命令」。后台不扫门户禁用词，但同一个东西全站只能一个叫法。

## 二、派模拟新手

- 每个测试员一个 `sonnet` 子 agent，零上下文：**只给地址和任务**，不给代码、设计稿、flow.md、正确路径。prompt 用 `templates/tester-prompt.md` 填空。
- `subagent_type` 用 `Explore`：它没有 Edit / Write，但有 Bash，所以全靠 prompt 禁止读文件、跑命令、看源码和用 `javascript_tool`。
- 一人一个端口、一个标签页，同时不超过 3 个：内置浏览器窗格是共用的，标签数有上限。
- **首次点击测试必须看截图**：派之前先 `tabs_context` 确认窗格是 displayed（窗格隐藏的坑见 flow-walk）。只靠 `read_page` 测出的结果要标「未看截图」，因为它会读到视觉上看不到的文字，成绩会偏好。
- 每个场景手机（375）和桌面（1280）各派一次，**不是同一个测试员换尺寸重做**，做过一遍的人已经学会了。
- 测试员交回后，总协调把原文存成 `tester-<场景>-<尺寸>.md`，位置见第五节。

## 三、逐页检查（总协调或带上下文的 sonnet 做，不是新手）

每个页面、弹层、结果页过一遍：

1. **375×812 与 1280×900，各浅色深色**，共四种。
   - 深色不能靠 `resize_window` 的 `colorScheme`：面板只认 `<html data-theme>`，默认浅色，不跟随系统。切深色要 `localStorage.setItem('pandora-theme','dark')` 后刷新，切回删掉这个键。
   - 每种跑一次 `scripts/page-check.js`：把文件内容整段作为 `javascript_tool` 的 `text`。它返回横向溢出的元素、禁用词命中（含 `aria-label`、`title`、`placeholder`、打开着的 `<dialog>`）和没有可读名字的按钮。
   - JS 错误用 `read_console_messages` 的 `onlyErrors`。
2. **禁用词 0 次**（门户）。词表以单测 `panel/frontend/tests/mock-portal-wording.test.ts` 为准，`page-check.js` 顶部的 `WORDS` 与它保持一致。「升级」只许出现在兑换不同款套餐卡的选项里；「流量重置卡」是卡名，不算「重置」。
3. 规则清单：

| 查什么 | 怎么算过 |
|---|---|
| 每个选择旁看得到结果 | 选项、开关、档位旁边就写出后果：到期日 A → B、今天付多少、链接变不变、退多少到哪。不靠点开「详情」 |
| 操作完给下一步 | 结果页、toast 说清现在的状态和下一步（例「App 里点一次更新」「新链接 + 添加到 App」），或明说「什么都不用做」 |
| 只有一个合理选项时不让选 | 一份时不出「给哪一份」；余额够付时不出付款方式 |
| 不可逆操作 | 确认框写明影响范围（只换哪一份、哪些设备要重新添加）；「换掉生效中的」永不默认 |
| 空状态 | `empty` 场景：每页说清为什么空、给一个去处，不是空白或「暂无数据」 |
| 出错 | `error` 场景：人话加重试，不露错误码、英文、堆栈 |
| 加载中 | `slow` 场景：骨架，不显示 0 或 ¥0.00，不跳版（报价算出来前「应付」是骨架） |
| 限频冷却 | 连点两次换新链接：说出还要等多久，不是笼统的「操作太频繁」 |
| 文案一致 | 同一个东西全站一个叫法（套餐 / 一份 / 链接 / App）；入口按钮、确认页标题、结果页三处动词一致 |
| 键盘 | Tab 能到每个可点的东西且看得见焦点；Enter 提交；Esc 关弹层，焦点回到触发按钮 |
| 体感 | 点击后立刻有按下态或加载态；提交中按钮不能再点 |

## 四、分级、修、复测

| 级别 | 定义 | 处理 |
|---|---|---|
| 卡住 | 3 次找不到、放弃，或完成不了任务 | 必修 |
| 犯错 | 以为做成了其实不是：加错份、换掉了不想换的、多付钱、以为付了没付、说错到期日或退款去向 | 必修 |
| 别扭 | 完成且正确，但绕了路、犹豫，或引用了看不懂的字 | 按根 CLAUDE.md「取舍原则」四栏判：体验变好、其余不变差就修 |

- 「一次点对」：点击路径就是最短路径，没有返回、没有点错；而且每次点击前写下的预期都和实际一样。
- 「犯错」比「卡住」更要紧：卡住的人会去问客服，犯错的人会觉得被坑。测试员交回里「担心扣错钱、担心现在的用不了」的时刻，至少记成「别扭」。
- 修完用**新的**测试员复测同一场景同一任务。原来那个已经学会了，不能当复测。
- 规则改动要回写权威：原型阶段改 `flow.md`（新一轮改动表），实现阶段改 `.claude/rules/screens-portal*.md`，禁用词改动同步门户叫法单测 `tests/mock-portal-wording.test.ts`（归门户路，不在本 skill 里改）。
- 新手反馈和已定的产品规则冲突时（例：用户已定「不同款套餐卡一律不预选」），不要自己改规则：写进报告，交总协调问用户。

## 五、记录

一张表，一个任务一行：

| 场景 | 任务 | 一次点对？ | 卡在哪 | 改了什么 |
|---|---|---|---|---|
| proto-s2 · 375 | 只给自己那份加流量 | 是 | — | — |
| proto-s4 · 1280 | 换便宜的，说出退多少到哪 | 否（犯错） | 说成「退回支付宝」：确认页写的是「退到余额」，没说余额在哪 | 确认页与结果页加「在『钱包』里，可用于续费、加流量、买套餐」；复测通过 |

- 「一次点对？」填 是 / 否（卡住、犯错或别扭）/ 未测（写原因）。
- 「卡在哪」引测试员原话，加页面上让他犹豫的那句原文。
- 表后另起两张小表：逐页检查（页面 × 四种尺寸主题：溢出、禁用词、JS 错误）和别扭项清单。最后一行写总结：环境（原型 / 假后端，前端目录与提交号）、测试员个数、一次点对率、必修几条、已修几条、复测结果。

放哪：

- 任务会话里做的：写进该 worktree 的 `.claude/report.md`「体验审查」一节；Agent 派的子 agent 写不了文件，就放进最终消息，由总协调代存。
- 总协调单独做的：`ops-local/reports/<日期>/ux-review-<范围>/`，放 `summary.md` 和测试员原文。
- 截图放会话 scratchpad，不进仓库。

## 坑

- **任务文字泄题**：任务里出现按钮上的字（续费、加流量、换新链接），一次点对率会虚高。写完任务对照页面文字查一遍。
- **原型 hint 是给总协调看的**，不能原样当任务给测试员：hint 里带着按钮名。
- **测试员越界**：sonnet 有时会去读 `read_page` 全树找按钮，或跑 JS 切场景。交回里出现页面上看不见的文字、或提到场景名时，这一条作废重派。
- **假后端不限频的地方**测不出冷却文案。哪些动作有限频，以 `dev/mock/portal/` 的实现为准，没模拟的在记录里写「未测（假后端未模拟）」，留到测试机上用 flow-walk 补。
- 内置浏览器的通用用法见 flow-walk，这里不重复：标签数上限、每个调用带 `tabId`、窗格隐藏时视口 0x0，在「操作方法」第 1、3 条；toast 不在 `<main>` 里、SSE 让网络永不空闲、假收银台整页跳转，在「坑」。
