## 服务器脚本测试红线

（派给 Composer 的「照脚本跑的 SSH 测试」，把本节原样抄进 brief，填好尖括号。用户 10-10 同意：Composer 可以在测试机上照 opus 写好、验过的脚本跑测试；故障注入、排查异常、开机删机、改 SSH 配置、结果判读仍归 Claude。Composer 读不到全局规则 `~/.claude/CLAUDE.md`，红线只能靠这一节。`cursor-launch.sh --dir` 会检查 brief 里有这个标题。）

**只许登录**：<别名 1>、<别名 2>…（都必须是测试机，不许是生产机）。**禁止登录**：清单外的任何机器，特别是 <别的业务的机器、别的路正在用的测试机的别名>。

违反下面任何一条就立刻停下，写进报告：

1. 动手前先读 `~/ai/servers/README.md`，再读每台的 `~/ai/servers/<别名>/AGENTS.md`，然后读机器上的 `/root/README.md`。三处写的规矩与本 brief 冲突时，以更严的为准。
2. **只跑下面列出的命令和脚本，逐字照抄，不改参数、不加步骤**：
   <逐条列出：在哪台机器、什么目录、跑什么命令或脚本（脚本由 opus 写好并放在 <路径>）、预计耗时、产出文件在哪>
   查看类命令随时可用：`uptime`、`free -m`、`df -h`、`ps`、`ss -s`、`systemctl is-active <单元>`、`ls`、`du -sh`、`cat` / `head` / `tail`（只读文本文件）。
3. **一律不做**：装软件或 apt；改 sysctl、内核参数、iptables、ufw；停服务、重启机器；kill 清单外的进程（要停自己起的进程，用记下的 PID：`kill <PID>`，不用 `pkill -f`）；改系统配置文件；开机、删机、改套餐；改本机 `~/.ssh/config` 或 `~/ai/servers/`。
4. ssh 只用 `ssh -n -o BatchMode=yes <别名> '<命令>'`：不用密码，不加 `-o StrictHostKeyChecking=no`；连不上就记下来，同一台重试不超过 3 次。
5. **远端后台进程**一律写成 `ssh -n <别名> 'cd <目录>; setsid -f ./<脚本> > <日志> 2>&1 < /dev/null'`，两台机器分两条命令发，并记下 PID；不用 `x &`。
6. **不读、不输出任何秘密**：不 cat `.env`、`*secret*`、`*.key`、`*cred*`、`/etc/pandora*/` 下的凭证文件、`~/.ssh/`；不读本机 `ops-local/**/secrets/`。口令只经 stdin 或 0600 文件传，不写进命令行。看到口令、令牌、私钥类内容，不抄进任何文件。
7. **IP 和域名不写进任何文件**：报告里只用别名；输出里的 IP、域名写进文件前换成 `<ip>`、`<domain>`。
8. 本机只许写 `<本次目录（主目录 ops-local/ 下）>`；不改 git 仓库里的任何文件，不提交、不推送。从机器上取回的只有清单里写明的结果文件。
9. **遇到异常就停**：命令报错、结果明显不对（例如 5xx、进程退出、数值离谱）、机器状态和预期不符，不要自己想办法补救或改步骤，记下现象和时间，停在原处写报告。
10. 收尾：停掉自己起的进程（用记下的 PID），确认机器回到开始时的状态（`ps`、`ss -s` 对照开始时的记录）；报告末尾如实写：跑过的命令清单与起止时间、自己起过的进程及是否已停、连不上或被拒的命令、有没有违反或接近违反红线的地方。
