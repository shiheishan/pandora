# Node release-artifact binding

First-time node enrollment is fail-closed in production unless the control
plane is configured with the exact native-node release that the installer is
allowed to activate. The values are deployment configuration, not user input
and must not be derived from request headers or bootstrap commands.

Set these variables in the panel service environment for each release:

```text
AEGIS_ENV=production
PANDORA_NATIVE_RELEASE_VERSION=<agent version embedded in the release>
PANDORA_NATIVE_ARTIFACT_AMD64_SHA256=<sha256 from SHA256SUMS>
PANDORA_NATIVE_ARTIFACT_ARM64_SHA256=<sha256 from SHA256SUMS>
```

The release operator must obtain the two architecture digests from the
`SHA256SUMS` file generated by `panel/deploy/build-release.sh`, verify the
file independently, and install the values before enabling node enrollment.
The panel compares the submitted `binary_sha256`, `architecture`, and
`agent_version` evidence with these values inside the commit transaction. A
missing production binding or any mismatch rejects the commit; development
and disposable test environments may omit the binding explicitly.

The installer also submits canonical SHA-256 evidence for the installed
config, non-root systemd unit, and `validate-install` preflight output. Those
values are persisted as the immutable `commit_evidence` JSON for audit and
cannot be changed after a committed enrollment.

Before accepting a release, verify both architecture entries are present in
the panel archive and that the panel service environment points at the same
release revision. Changing the native artifact or version requires updating
these variables and following the documented signing-key/enrollment rollout;
do not mix values from different release archives.

The schema-changing maintenance controller has a separate supply-chain gate:
invoke it with `PANDORA_RELEASE_MANIFEST_SHA256` set from the out-of-band
`<archive>.manifest.sha256` sidecar. It rejects missing or mismatched manifests
and refuses source trees or parents that are not root-owned and non-writable.
