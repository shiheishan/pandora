# 上手教程：从零搭到用户能用

写给第一次搭 Pandora 面板的站长。你会用 ssh、会复制命令就够了，不需要懂项目内部。

照着做完，你会得到：

- 一个能打开的面板，后台能登录；
- 至少一台在线的节点；
- 一个在售的套餐；
- 一个测试账号：注册、付款、拿到链接、添加到 App 后能连上。

约定：

- 文中的 `panel.example.com`、`node1.example.com`、`203.0.113.10`（面板机）、`203.0.113.20`（节点机）、`admin@example.com`、`<后台前缀>` 都是占位，换成你自己的。
- 后台菜单写成「侧栏菜单 › 页签」，例如「节点与服务器 › 服务器」。按钮名照页面上显示的文字写。
- 每一步最后都有「卡住了」，链到排障手册 [RUNBOOK](../panel/deploy/RUNBOOK.md) 的对应章节。
- 这里只讲怎么做。原理看 [README](../README.md) 和 [docs/architecture.md](architecture.md)。

---

## 你需要准备什么

- [ ] **一台面板机**：Debian 12–14 或 Ubuntu 22.04–26.04，x86_64 或 aarch64，能用 root 登录（第 1 步）。
- [ ] **至少一台节点机**：Linux，x86_64 或 aarch64，有 systemd，能用 root 登录。可以先和面板机共用，利弊见第 1 步。
- [ ] **域名（推荐）**：一个给面板，例如 `panel.example.com`；节点可以用域名，也可以直接用 IP（第 2 步）。
- [ ] **云服务商控制台的权限**：要改安全组 / 防火墙（第 3 步）。
- [ ] **一个邮箱做管理员账号**：例如 `admin@example.com`。管理员口令至少 12 位，同时有字母和数字。
- [ ] **另一个邮箱做测试用户**：管理员账号不能登录用户端（第 9 步）。
- [ ] **SMTP 发信账号（推荐）**：没有它，注册验证邮箱、找回密码都用不了（第 5 步）。
- [ ] **支付渠道的商户资料**：易支付、BTCPay Server 或 CoinPayments 其中之一（第 6 步）。
- [ ] **一个代理客户端 App**：装在你自己的手机或电脑上，第 9 步测试用。

## 第 1 步：买服务器

### 做什么

买一台面板机、至少一台节点机。

### 面板机要求

| 项 | 要求 |
|---|---|
| 系统 | Debian 12–14 或 Ubuntu 22.04–26.04（安装器只认这两种） |
| 架构 | x86_64 或 aarch64 |
| 权限 | root，有 systemd |
| 预装 | `curl`、`openssl`（安装器会用 apt 装 PostgreSQL 18、Redis、nginx 等） |
| 内存 | 建议 2 GB 起。安装器给各服务设的内存上限合计约 1.7 GB：面板 512 MB、后台任务 256 MB、PostgreSQL 512 MB、Redis 384 MB |
| 磁盘 | 留出数据库和每日备份的空间（备份在 `/var/backups/pandora/`） |
| 网络 | 能访问 GitHub（下载安装包）、系统软件源、Let's Encrypt |

想用公网 IP 直接装（不用域名），**选 Debian**。原因见第 2 步。

### 节点机要求

| 项 | 要求 |
|---|---|
| 系统 | Linux，有 systemd；装面板的那两种系统最省事 |
| 架构 | x86_64 或 aarch64 |
| 权限 | root |
| 规格 | 测试用 1 核 1 GB 能跑；正式按用户数和带宽买 |
| 网络 | 能连到面板的 443 和 9443；能访问 Let's Encrypt（自动申请证书时） |

### 一台还是两台

可以先把节点装在面板机上试流程，正式上线前再分开。

| | 同一台 | 分开两台 |
|---|---|---|
| 钱 | 省一台 | 多一台 |
| 端口 | 80、443 被面板的 nginx 占着，9443 是面板的节点通道。节点只能用别的端口 | 节点随便选（22、25、53、80 除外） |
| 节点证书 | 自动申请证书要用 80 端口，同一台申请不了。只能选不需要证书的协议（VLESS + REALITY、Shadowsocks），或者手填证书 | 可以自动申请 |
| 安全 | 节点和面板用同一个系统用户 `pandora`，节点进程读得到面板的密钥文件 `/etc/pandora/secrets.env`。节点是对公网开放的，被攻破就连带面板 | 互不影响 |
| 稳定 | 节点流量和面板抢 CPU 与带宽；这个 IP 被封，面板也打不开 | 互不影响 |

结论：**同一台只拿来试流程，正式上线一定分开。**

### 看到什么算成功

两台机器都能用 root 登录：

```bash
ssh root@203.0.113.10
```

### 卡住了

- 系统版本不对：安装器在第一步就会停下，提示只支持哪些系统。换系统重装再来。

## 第 2 步：域名解析（或者直接用 IP）

### 做什么

在域名服务商那里加 A 记录：

| 主机记录 | 类型 | 指向 |
|---|---|---|
| `panel` | A | 面板机的公网 IPv4，例如 `203.0.113.10` |
| `node1` | A | 节点机的公网 IPv4，例如 `203.0.113.20`（节点用域名时才要） |

注意：

- **只解析，不开 CDN 代理**（例如 Cloudflare 的橙色云先关成灰色）。节点要直连面板的 9443 端口，也要让 Let's Encrypt 直连 80 端口验证证书，经过 CDN 会失败。
- 有 AAAA（IPv6）记录的，要确认也指向同一台机器，并且 IPv6 能通；不确定就先别加 AAAA。

### 用域名还是直接用 IP

安装时问「面板对外地址」，可以填 `https://panel.example.com`，也可以直接回车用本机公网 IP。

| | 用域名 | 用公网 IPv4 |
|---|---|---|
| 面板证书 | Let's Encrypt 域名证书，约 90 天，自动续期 | Let's Encrypt IP 证书，约 6 天，自动续期 |
| 系统要求 | 无 | 申请 IP 证书要 lego 4.22 以上。安装器只在 **Debian** 上自动装。Ubuntu 上申请不到，会退回自签证书（浏览器提示不安全） |
| 用户看到的地址 | 域名 | 一串 IP |
| 以后换地址 | 后台改「主域名」，按 [RUNBOOK 第 15 章](../panel/deploy/RUNBOOK.md#15-换主域名) 的顺序做 | 同左 |

推荐用域名。没有域名就用 Debian + IP。

面板落在自签证书上会怎样：浏览器提示不安全；支付渠道可能推不进回调；节点安装命令用 `curl` 下载脚本时校验证书，会失败。所以**装节点之前，面板必须是正规证书**。

### 看到什么算成功

在自己电脑上查，返回面板机的 IP：

```bash
dig +short panel.example.com
```

### 卡住了

- 查不到或 IP 不对：等几分钟到几小时让解析生效，再查。
- 证书申请失败、域名解析相关：[RUNBOOK 第 4 章](../panel/deploy/RUNBOOK.md#4-面板-https-证书续期失败)。

## 第 3 步：放行端口

### 做什么

在云服务商控制台的**安全组 / 防火墙**里放行入站端口。

**面板机**：

| 端口 | 协议 | 干什么 |
|---|---|---|
| 22 | TCP | ssh（你自己登录用） |
| 80 | TCP | 申请和续期 HTTPS 证书；其他请求会跳到 443 |
| 443 | TCP | 用户端和后台 |
| 9443 | TCP | 节点连面板（gRPC，节点机必须能连上） |

PostgreSQL、Redis、面板自己的 9000 / 9001 只听本机，**不要**放行。

**节点机**：

| 端口 | 协议 | 干什么 |
|---|---|---|
| 22 | TCP | ssh |
| 80 | TCP | 节点自动申请证书（HTTP-01 验证）。只用 VLESS + REALITY、Shadowsocks 这类不要证书的协议时可以不开 |
| 节点端口 | 看协议 | 第 7 步给节点填的端口 |

节点端口放 TCP 还是 UDP：

- Hysteria2、TUIC、Juicity：UDP。
- Shadowsocks：同一个端口 TCP 和 UDP 都放。
- Mieru：传输方式选 UDP 时放 UDP，否则 TCP。
- VLESS、VMess 选了 xhttp-h3 或 mKCP 传输时放 UDP；Trojan 选 mKCP 时放 UDP。
- 其余（VLESS、VMess、Trojan、AnyTLS、Naive、ShadowTLS、SOCKS、HTTP 的常规用法）：TCP。

### 机器自己的防火墙

- 面板机：安装器发现 ufw 或 firewalld 开着时，会自己放行 80、443、9443。都没开时它会提示「云厂商安全组要放行 80、443、9443/tcp」。
- 节点机：安装脚本**不动**防火墙。机器上开了 ufw 的，自己放行，例如：

```bash
ufw allow 80/tcp
```

### 看到什么算成功

这一步先改好规则。真正的验证在后面：第 4 步证书申请成功说明 80 通；第 7 步服务器显示「已接入」说明 9443 通。

### 卡住了

- 证书申请失败：多半是 80 没通，[RUNBOOK 第 4 章](../panel/deploy/RUNBOOK.md#4-面板-https-证书续期失败)。
- 节点连不上面板：[RUNBOOK 第 3 章](../panel/deploy/RUNBOOK.md#3-节点离线或不上报心跳)。

## 第 4 步：一条命令装面板

### 做什么

ssh 登录面板机，在 shell 里跑：

```bash
curl -fsSL https://github.com/shiheishan/pandora/releases/latest/download/get.sh | sudo bash
```

它会下载最新正式版、核对校验和，然后跑安装器。安装器分 8 步，屏幕上会依次出现 `[1/8] 安装系统依赖` 到 `[8/8] 管理员与 HTTPS`。任何一步失败都会停下，并说明停在哪、怎么办。

已经有 Docker 或 1Panel 环境的，也可以用容器装，见 [panel/deploy/docker/README.md](../panel/deploy/docker/README.md)。本教程按上面的一条命令写。

### 会问什么、怎么答

**问题一：面板对外地址**

```text
    面板对外地址（接入命令、支付回调、订阅链接都从它拼出来）：
      有域名填 https://你的域名；没有域名用本机公网 IP，装完自动申请 IP 证书
    [直接回车用 https://203.0.113.10]
```

- 有域名：输入 `https://panel.example.com`，回车。
- 没域名：直接回车，用方括号里的本机公网 IP。
- 不要带端口和路径，必须是 `https://` 开头。不合规会在动手之前停下。
- **想清楚再填**。接入命令、支付回调、订阅链接、节点连面板的地址都从它来，装完不建议再改。

**问题二：第一个管理员**

```text
    现在创建第一个管理员（直接回车跳过，之后再手工建）。
    管理员邮箱：
    密码（不回显）：
    再输一次：
```

- 邮箱填你的管理员邮箱，例如 `admin@example.com`。
- 密码至少 12 位，同时有字母和数字。输入时屏幕不显示，正常。
- 网页上没有建管理员的入口，**建议现在就建**。跳过了也行，装完按下面「没建管理员」的命令补。

### 看到什么算成功

第 7 步后面有这几行：

```text
  pandora-serve: active
  pandora-worker: active
  公开 readyz :9000 → 200
  管理 readyz :9001 → 200
```

最后是总结：

```text
Pandora 安装完成
  现在可以做什么：
    打开管理后台：https://panel.example.com/<后台前缀>/
  （这个地址就是后台入口，别外传）
```

- `<后台前缀>` 是安装时随机生成的一长串，等于后台的门牌号。**记下来，别外传。**
- 「还差什么」里列着没做完的事，例如开每日备份、把备份解密私钥另存。可以先往下走，上线前回来做（见文末「上线前再检查」）。
- 总结里如果有「换上正规证书（现在是自签）」，说明证书没申请下来。先按第 2、3 步检查域名和 80 端口，修好后跑：

```bash
sudo /opt/pandora/deploy/edge-tls.sh issue
```

### 忘了后台地址

在面板机上跑：

```bash
sudo /opt/pandora/deploy/admin-url.sh
```

### 没建管理员

安装时跳过了，用这条补（口令从标准输入读，不进命令行）：

```bash
read -rsp '密码：' p && echo && printf '%s\n' "$p" | sudo systemd-run --pipe --quiet --uid=pandora -p EnvironmentFile=/etc/pandora/secrets.env /opt/pandora/bin/pandora admin create --email admin@example.com --password-stdin; unset p
```

### 以后升级

再跑一次同一条 `curl … | sudo bash`。它会先备份数据库再换程序。

### 卡住了

- 提示「没有终端可以提问」：你不是在交互式 shell 里跑的（例如 cloud-init、`ssh 主机 '命令'` 没带 `-t`）。用 `ssh root@203.0.113.10` 登录进去再跑；无人值守的写法见 [README「部署」第 1 节](../README.md#1-一条命令装github-release)。
- 安装中途失败，提示迁移失败：[RUNBOOK 第 10 章](../panel/deploy/RUNBOOK.md#10-迁移失败)。
- 服务起不来、健康检查没通过：先看 [RUNBOOK 第 0 节](../panel/deploy/RUNBOOK.md#0-先看全貌只读)，再看 [第 1 章](../panel/deploy/RUNBOOK.md#1-面板-5xx--服务起不来)。
- 证书是自签、申请失败：[RUNBOOK 第 4 章](../panel/deploy/RUNBOOK.md#4-面板-https-证书续期失败)。

## 第 5 步：打开后台、登录、做站点设置

### 5.1 登录

1. 浏览器打开安装时给的后台地址：`https://panel.example.com/<后台前缀>/`。**结尾的 `/` 不能少。**
2. 填「管理员邮箱」和「密码」，点「登录」。

**成功**：提示「登录成功，正在进入控制台」，进到「仪表盘」。左侧菜单分组是：仪表盘、工单；业务（用户、套餐、订单与收款、营销）；网络（节点与服务器）；设置（内容与外观、通知与插件、安全与运维）。

很多保存操作会弹「验证身份后继续」，输入「当前登录密码」，刚才的操作会自动继续。

改管理员密码：左下角点自己的名字 → 「修改密码」。改完这个账号的后台会话全部退出，用新密码重新登录。

### 5.2 站点名和时区

**在哪点**：「内容与外观 › 主题与插槽」→「站点设置」卡片。

- **站点名**：用户端标题、浏览器标签、邮件发件人名、订阅配置名都用它。缺省是 `Pandora`，改成你的站名。
- **时区**：缺省是「中国 · 上海」（北京时间）。用户端用量按天统计、后台收入趋势都按它切日。用户主要不在中国大陆的，改成他们所在的时区。改了只影响之后的数据，所以**趁早改**。
- **主域名**：**先留空**。留空就用安装时的地址。以后要换域名，按 [RUNBOOK 第 15 章](../panel/deploy/RUNBOOK.md#15-换主域名) 的顺序做，先让新域名能打开面板，再回来填。

点卡片底部的「保存」。**成功**：提示「站点设置已保存」，左上角的站点名跟着变。

### 5.3 配邮件（SMTP）

**在哪点**：「通知与插件 › 通知渠道」→「发送渠道」里「邮件」那一行 →「配置」。

在「SMTP 邮件」弹窗里填：

| 项 | 填什么 |
|---|---|
| 服务器 | 发信服务器地址，例如 `smtp.example.com` |
| 端口 | 缺省 465 |
| 加密 | SSL（465 直连）/ STARTTLS（587）/ 不加密 |
| 用户名、密码 | 发信账号 |
| 发件人 | 例如 `Pandora <noreply@example.com>` |

点「保存」。再在弹窗底部「测试收件地址」填你自己的邮箱，点「发送测试」。测试用的是已保存的配置，所以先保存再测。

**成功**：「邮件」那一行标着「已配置」，你收到测试信。

**没配 SMTP 时**，下面这些用不了：

- 注册时验证邮箱：开不了，保存会提示先填好 SMTP。
- 找回密码：用户端登录页不显示「忘记密码？」。
- 用邮件里的链接登录：用不了。
- 所有邮件通知都不发。

管理员忘了口令不走邮件，在服务器上重置，见 [RUNBOOK 第 2 章](../panel/deploy/RUNBOOK.md#2-管理员进不来)。

### 5.4 注册方式

**在哪点**：同一页下面「注册与验证」那一行 →「配置」。

- **注册模式**：开放 / 仅邀请 / 关闭。新装缺省是「开放」。
- **注册时验证邮箱（发送验证码）**：缺省关。配好 SMTP 后建议打开，防止有人用别人的邮箱乱注册。

**成功**：那一行写着例如「开放注册 · 需验证邮箱」。

### 卡住了

- 后台地址打不开、404、证书不安全、提示「邮箱或密码不正确」：[RUNBOOK 第 2 章](../panel/deploy/RUNBOOK.md#2-管理员进不来)。
- 测试信发不出去、邮件积压：[RUNBOOK 第 6 章](../panel/deploy/RUNBOOK.md#6-通知积压)。

## 第 6 步：配支付

### 有哪些渠道

| 渠道 | 用户怎么付 | 后台要填的凭据 |
|---|---|---|
| 易支付 | 支付宝、微信支付 | 站点地址、商户号（pid）、商户密钥；下单路径、查询接口路径有缺省值 |
| BTCPay Server | 在 BTCPay 收银台里选币付款 | BTCPay 服务地址、Store ID、API Key、Webhook 密钥 |
| CoinPayments | 在 CoinPayments 收银台里选币付款 | Client ID、Client Secret；API 地址留空用官方地址 |

另外：

- 用户也可以用钱包**余额**付。
- 列表里有一个内置的「线下收款」渠道，只读、不能改，后台「标记已支付」「人工开单」时用。
- 整个系统只有人民币。加密货币渠道按人民币开发票，BTCPay 商店的汇率源要支持 CNY。
- 不支持退款。

### 做什么

1. **在哪点**：「订单与收款 › 支付渠道」→ 右上「新建渠道」。
2. 选「渠道类型」，填「渠道编码」（回调地址里会用到，建好不能改）和「名称」，再填上表的凭据。
3. 可选：「最低付款额（元）」留空按 1.00；「固定手续费（元）」「比例手续费（%）」是向用户加收的，都填 0 就是不收。
4. 点「创建」。

新建的渠道是「已启用、暂停收新单」，用户还看不到。核对无误后：

5. 在列表里打开这个渠道的「收新单」开关，确认。
6. 等最多 5 分钟，用户端结账页才会出现它。

加密货币渠道还要做：

- **BTCPay**：在 BTCPay 商店「Settings › Webhooks」里新建 Webhook，地址填列表里这个渠道的「回调地址」，事件勾选 Invoice settled / expired / invalid，密钥和后台填的 Webhook 密钥一样。商店的付款容差保持 0。
- **CoinPayments**：回调地址随发票自动下发，不用配。在商户后台关掉「接受部分付款」，少付容差设为 0。

易支付的回调地址也随订单下发，不用在易支付后台配。

### 怎么测

测试要一个用户账号。先按 [9.1](#91-注册一个测试账号) 注册一个测试账号，再回来：

1. 用测试账号登录用户端，进「钱包」，点「充值」。
2. 金额选「其他」，填 1（最少 1 元）。
3. 点底部的「充值 ¥1.00」（金额格式以页面为准），选刚建的渠道，在收银台付款。
4. 付完回到页面会自动更新；没更新就点「我已付款」。

**成功**：

- 用户端「钱包」余额多了 1 元。这 1 元留在余额里，第 9 步买套餐可以用。
- 后台「订单与收款 › 订单」里有这笔充值，状态是已支付。
- 「支付渠道」列表里这个渠道的「今日成交」有数。

### 卡住了

- 结账页写「暂无可用的支付方式，请稍后再试。」：渠道没打开「收新单」，或者还没到 5 分钟。
- 付了钱没到账：先在后台订单详情里点「向渠道查单」；还不行看 [RUNBOOK 第 5 章](../panel/deploy/RUNBOOK.md#5-支付回调没到账--订单卡住)。
- 面板证书是自签或过期，渠道推不进回调：[RUNBOOK 第 4 章](../panel/deploy/RUNBOOK.md#4-面板-https-证书续期失败)。

## 第 7 步：加服务器、装节点、上线

顺序是：节点池 → 服务器 → 在节点机上跑安装命令 → 新建节点 → 上线。后台「节点与服务器 › 节点」页签栏右边的「?」里也有同样的步骤。

### 7.1 建一个节点池（只需一次）

节点池决定节点给谁用：节点归进池，套餐绑定池，买了套餐的用户才拿到池里的节点。

1. **在哪点**：「节点与服务器 › 节点池」→ 右上「新建节点池」。
2. 填「名称」，例如「标准线路」。「标识」留空会按名称生成。
3. 点「保存」。

**成功**：列表里出现这个池，写着「没有绑定套餐，暂时不服务任何用户」。正常，第 8 步绑。

### 7.2 添加服务器，拿安装命令

1. **在哪点**：「节点与服务器 › 服务器」→ 右上「添加服务器」。
2. 填「名称」（例如 `node1`）和「容量（最多几个节点）」。地区、IP、系统在机器接入后自动回填。
3. 点「添加并签发安装令牌」，按提示输入当前登录密码。
4. 弹出「安装 agent · 接入面板」，第 1 步是一条安装命令，点「复制」。

注意：

- 命令里带一次性令牌，**30 分钟内有效，关掉弹窗就再也看不到**。
- 过期或丢了：在服务器卡片上点「安装令牌」重新签发。

### 7.3 在节点机上跑安装命令

ssh 登录节点机，粘贴刚才复制的整条命令。它长这样（不要照抄，用后台给的）：

```bash
curl --proto '=https' -fsSL 'https://panel.example.com/pdnd/install.sh' | sudo bash -s -- --panel 'panel.example.com:9443' --ca-sha256 'sha256:<指纹>' --token '<令牌>'
```

脚本会下载节点端、核对校验和、用令牌接入面板、注册成系统服务 `pandora-native`。

**成功**：

- 节点机上最后出现「安装完成，服务已运行。」
- 后台这台服务器的卡片写「已接入：新建节点或把节点绑到这台，节点上线时这台自动投入服务」，地区和 IP 自动填上了。

### 7.4 新建节点

1. **在哪点**：「节点与服务器 › 节点」→ 右上「新建节点」。也可以直接点安装弹窗里的「新建节点（预选这台）」。
2. 向导分三步：

**第一步：协议**。点一张协议卡片。

第一个节点建议：

- 分开两台机器：随意。想省事选 **VLESS**（缺省用 REALITY，不需要证书）。想用证书类协议（Trojan、Hysteria2 等），缺省会自动申请证书，见 7.5。
- 和面板同一台：只选 **VLESS**（REALITY）或 **Shadowsocks**，原因见第 1 步。

**第二步：连接信息**。

| 项 | 填什么 |
|---|---|
| 节点名称 | 用户在 App 里看到的名字，例如 `HK-01` |
| 地区 | 必填，下拉里选 |
| 地址 | 用户连接用的域名或 IP，例如 `node1.example.com` 或 `203.0.113.20` |
| 端口 | 用户连接的端口。不能用 22、25、53、80；和面板同一台时也别用 443、9443。记得在第 3 步放行 |
| 所在服务器 | 选 7.2 加的那台 |
| 节点池 | 必填，选 7.1 建的池 |

**第三步：协议参数**。表单按协议显示要填的项，大部分有缺省值。

- VLESS（REALITY）：填「REALITY 目标站（dest）」和「REALITY SNI」（一个支持 TLS 1.3 的外部大站，输入框里有示例格式），再点「生成密钥对」，私钥、公钥、short_id 会自动填上。
- 带证书的协议：「证书来源」缺省是「自动申请（Let's Encrypt）」，见 7.5。
- 不懂的高级参数不用动，缺省是收起的。

3. 点「创建草稿」。

**成功**：跳到节点详情页，页头有「草稿」状态。

### 7.5 节点证书怎么来

只有带证书的协议要管：Trojan、Hysteria2、TUIC、Juicity、AnyTLS、Naive，以及开了 TLS 的 SOCKS / HTTP。VLESS + REALITY、Shadowsocks 不需要。

**缺省：自动申请（Let's Encrypt）**。节点端自己申请、自动续期，面板不碰私钥。条件：

- 节点的「客户端 SNI」或「地址」就是证书的名字。用域名时，A 记录要先指向节点机；用 IP 时直接用公网 IP（证书约 6 天，自动续）。
- 节点机的 80/TCP 从公网能连上，而且机器上没有别的程序占着 80。
- 选自动申请即视为同意 Let's Encrypt 订户协议。

申请过程中节点显示「等待证书」，入站先不开。证书一到自动开，不用重启。

续期失败时节点**继续服务**，到期后状态标「证书已过期」（降级）。这时客户端校验证书会失败，订阅里它排到后面。修好后自动恢复。

**另一种：手填证书路径**。自己用 certbot / acme.sh 把证书放到节点机，表单里填路径，见 [docs/node-certificates.md](node-certificates.md) 第 2 节。

### 7.6 上线

1. 在节点详情页右上角点「上线节点」。
2. 服务器会同时转为「服务中」。

**成功**：

- 提示「已上线：节点进入服务，服务器已就绪」。池还没绑套餐时，会多一条提醒，正常。
- 详情右侧「运行状态」是「运行中」（带证书的协议在拿到证书前是「等待证书」）。
- 「是否下发」现在写「所在节点池没有绑定任何套餐，不会出现在任何用户的订阅里」。正常，第 8 步绑好后会变成「正在下发给用户」。
- 「服务器」页这台机器的圆点是绿的。

### 卡住了

- 安装命令报错、接入失败、令牌过期：[RUNBOOK 11.4](../panel/deploy/RUNBOOK.md#114-接入装到一半卡住)。
- `curl` 报证书错误：面板还是自签证书，回第 2、4 步把面板证书弄好。
- 服务器卡片一直没变成「已接入」，或心跳断了：[RUNBOOK 第 3 章](../panel/deploy/RUNBOOK.md#3-节点离线或不上报心跳)。从节点机测 9443 通不通：

```bash
timeout 5 bash -c '</dev/tcp/panel.example.com/9443' && echo reachable
```

- 节点显示「生效失败：端口 … 被占用」：[RUNBOOK 11.1](../panel/deploy/RUNBOOK.md#111-端口被占)。
- 「等待证书」很久不消失、「证书申请失败」：[RUNBOOK 11.5](../panel/deploy/RUNBOOK.md#115-节点证书申请失败cert_pending-久不消失cert_expired仪表盘证书异常)。
- 其他节点机侧问题：[RUNBOOK 第 11 章](../panel/deploy/RUNBOOK.md#11-节点机侧pdnd)。

## 第 8 步：建套餐并发布

### 两类套餐

| | 订阅套餐（用户端叫「按时间」） | 一次性套餐（用户端叫「一次性」） |
|---|---|---|
| 怎么卖 | 按月 / 季度 / 半年 / 年，填了价格的周期才卖 | 一个价格 |
| 流量 | 每个周期一份，新周期清零 | 一份总流量，不清零，用完为止 |
| 到期 | 用户自己续费 | 有效天数，留空为永久；不能续费 |

价格只有人民币。流量单位 GB 按 1024³ 字节算。

### 做什么

1. **在哪点**：侧栏「套餐」→ 右上「新建」。
2. 在弹窗里从上往下填：

| 小节 | 填什么 |
|---|---|
| 类型 | 「订阅套餐」或「一次性套餐」 |
| 名称、说明（选填） | 说明显示在用户端套餐卡上 |
| 价格 | 订阅：「每月（元）」「每季度（元）」「每半年（元）」「每年（元）」，空着的不卖。一次性：「价格（元）」和「有效期（天）」（留空为永久） |
| 额度 | 「每周期流量（GB）」或「总流量（GB）」，「设备上限」；留空为不限 |
| 线路 | 打开第 7 步建的节点池的开关。**改线路立即生效** |
| 流量重置 | 可选：「允许用户付费重置流量」，填每次价格和次数上限 |
| 上架 | 「创建后立即上架」，打开就直接开卖 |

3. 点「创建订阅套餐」（或「创建一次性套餐」）。

关掉「创建后立即上架」时，套餐先存为草稿。之后在套餐详情页右上角点「发布 v1」（或到「版本」页签发布）。

### 看到什么算成功

- 提示「已创建并上架」，套餐列表里状态是「在售」。
- 回到第 7 步那个节点的详情页，「是否下发」变成「正在下发给用户」。

### 以后改套餐

- 线路：立即生效。
- 价格：只影响之后的购买。
- 流量、设备、限速：先存成草稿版本，发布后新购使用；订阅老用户下个周期切换，一次性老用户不受影响。
- 只想暂停售卖：在详情「销售」里关掉「允许新购」。「归档」不能恢复，老用户也不能续费，慎用。

### 卡住了

- 创建时报「发布前至少绑定一个节点池」：「线路」里一个池都没开。
- 报「绑定池中至少需要一个可服务节点」：池里还没有在线节点。回第 7 步，确认节点已「上线节点」、服务器已接入并有心跳。
- 详情「概览」顶部提示「还没有绑定线路」或「绑定的节点池里没有可下发的节点」：点提示里的「去线路」处理。

## 第 9 步：用户注册、购买、用上

站长用一个测试账号把用户的路走一遍。**管理员账号不能登录用户端**，要用另一个邮箱。

### 9.1 注册一个测试账号

1. 浏览器打开用户端：`https://panel.example.com/`（不带后台前缀）。
2. 点首页右上的「注册」（或进登录页后切到「注册」）。
3. 按页面填：
   - 没开邮箱验证：填「邮箱」「邀请码」（选填）、「设置密码」（至少 8 位，字母和数字都要有），点「注册」。
   - 开了邮箱验证：填「邮箱」，点「发送验证码」；收到 6 位验证码后填「验证码」和「设置密码」，点「完成注册」。

**成功**：提示「注册成功，欢迎使用」，进到「我的套餐」，写着「你还没有套餐」和三步说明：选套餐、付款 → 复制链接 → 添加到 App。

### 9.2 买套餐、付款

1. 点「去选购」（或左侧「选购」）。
2. 在套餐卡上点「买<套餐名>」（一次性套餐是「买这个」）。
3. 在确认页选「买多久」，需要的话填优惠码；有余额时余额开关缺省打开；选付款方式。
4. 点主按钮。按钮文字写着这一单怎么付，例如「买标准版，付 ¥30.00」；余额够付时是「…用余额付 ¥30.00」，已有一份同款时开头是「买一份新的」。
   按钮灰着写「暂时没有能用的付款方式」：后台还没有收新单的付款渠道（第 6 步），余额也不够付。
5. 付款页：
   - 手机上点「打开支付宝付款」（按渠道不同，文字会变）。
   - 电脑上用手机扫二维码，或点「在这台电脑上付款」。
6. 付完回到这个页面会自动跳到完成页。没跳就点「我已付款」。

订单 30 分钟内不付会自动取消。

**成功**：完成页写着发生了什么，最上面是新链接和「添加到 App」。后台「订单与收款 › 订单」里能看到这一单。

### 9.3 拿链接、添加到 App

1. 在完成页，或「我的套餐」的套餐卡上，点「添加到 App」。
2. 选「就是现在这台」（在这台手机或电脑上打开 App 添加），或「别的设备」（把链接发过去，或当面扫码）。
3. 按页面提示在 App 里添加。没有页面推荐的 App，就点「复制链接」，在 App 添加订阅的地方粘贴。

**成功**：App 里出现第 7 步建的节点（名字是你填的节点名称），选它能连上、能打开网页。

### 9.4 不想花钱先验证节点：后台赠送

只想验证节点和订阅链接，不想走付款：

1. 后台「订单与收款 › 订单」→ 右上「人工开单」。
2. 「用户」搜测试账号的邮箱，「套餐与周期」选刚建的套餐。
3. 「结算方式」选「赠送（0 元）」，填「开单原因（写入审计）」，例如「测试」。
4. 点「赠送开通」，按提示输入当前登录密码。

**成功**：测试账号的「我的套餐」里出现这份套餐，接着按 9.3 添加到 App。

付款渠道本身的测试见第 6 步「怎么测」（充值 1 元）。

### 卡住了

- 「选购」里看不到套餐：套餐不是「在售」，或者在详情「销售」里设了可见范围、关了新购。
- App 里一个节点都没有：后台套餐详情「概览」顶部会提示原因；节点详情「是否下发」写着为什么不下发。
- 有节点但连不上：
  - 节点详情「运行状态」不是「运行中」：[RUNBOOK 第 11 章](../panel/deploy/RUNBOOK.md#11-节点机侧pdnd)。
  - 节点端口在安全组里没放行，或 TCP / UDP 放错了：回第 3 步。
  - 证书类协议「证书已过期」或还在「等待证书」：[RUNBOOK 11.5](../panel/deploy/RUNBOOK.md#115-节点证书申请失败cert_pending-久不消失cert_expired仪表盘证书异常)。
- 付了钱没开通：[RUNBOOK 第 5 章](../panel/deploy/RUNBOOK.md#5-支付回调没到账--订单卡住)。
- 以后加了专门的订阅域名，链接打不开：[RUNBOOK 第 14 章](../panel/deploy/RUNBOOK.md#14-订阅域名打不开)。

## 上线前再检查

先过一遍 README 的 [上线前检查](../README.md#上线前检查)（只开放该开的端口、数据库只听本机、给后台路径再加一层保护、限速、备份私钥另存、不把密钥写进仓库）。另外对照本教程补这几项：

- [ ] 面板和节点**分开两台机器**（第 1 步）。
- [ ] 面板证书是 Let's Encrypt 正规证书，不是自签：

```bash
sudo /opt/pandora/deploy/edge-tls.sh status
```

- [ ] 开了每日备份，并把备份解密私钥 `/etc/pandora/backup-age.key` 另存到机器之外。没有它，机器丢了任何备份都解不开。先做一份，再开定时：

```bash
sudo /opt/pandora/deploy/backup-postgres.sh
```

```bash
systemctl enable --now pandora-backup.timer
```

- [ ] 后台「仪表盘」的系统状态里没有要处理的红黄项（没配备份之前会一直提醒，是真提醒，见 [RUNBOOK 第 9 章](../panel/deploy/RUNBOOK.md#9-备份校验与恢复)）。
- [ ] 站点名、时区改好了；SMTP 配好、测试信收到了；需要的话打开了注册邮箱验证（第 5 步）。
- [ ] 用测试账号完整走过一遍注册 → 付款 → 添加到 App → 连上（第 6、9 步）。
- [ ] 后台地址只有管理员知道。忘了用 `sudo /opt/pandora/deploy/admin-url.sh` 查。
- [ ] 站点要放到 Cloudflare 代理后面的，按 README「4. 装完」配真实来源 IP；节点连面板的 9443 不能走 CDN 代理。
- [ ] 想给用户写 App 使用说明，放在「内容与外观 › 知识库」，用户在用户端「帮助中心」里看。

日常排障从 [RUNBOOK 第 0 节](../panel/deploy/RUNBOOK.md#0-先看全貌只读) 开始。
