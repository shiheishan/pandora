用户（管理后台-03-用户.dc.html）。「用户列表」标签是列表 + 560 宽详情抽屉，状态全在地址上：#/users/list/<用户 id>/<抽屉标签>?f=<状态>&g=<用户组>&q=<搜索>&o=<偏移>，刷新、分享、从仪表盘排行或工单「查看用户」点进来都落在同一处。第 ④ 步接入其余四个标签：用户组（表格 + 新建卡片，行内编辑，删除前按引用拦截）、批量运营（按条件预览 → 导出 / 群发，右栏批量生成）、设备策略（全局判定模式 + 接近上限的订阅，点行按邮箱找到用户打开抽屉「订阅」）、流量重置（统计、按邮箱手动重置、?r=&o= 在地址上的分页日志）；抽屉加「流量重置」标签与「立即重置本期」。
保留规则 2 贯穿整个模块：后台看不到订阅地址。列表、详情、画像都不含令牌；订阅标签用一句说明代替设计稿的「订阅地址 + 复制」；换发订阅链接只选订阅、填原因，响应 schema 用 strict 守住「不回令牌」（5.A D-B-1 / R11），成功后提示让用户到门户重新复制。搜索框按订阅令牌反查只比哈希，同样不暴露地址。
权限分层：iam.user.read 看列表、抽屉、用户组、批量预览与设备策略；iam.user.write 才有启停封禁、设新密码、换发、分组与设备上限、用户组增删改、批量导出与生成、改全局设备模式；ops.notification.write 才能群发；catalog.read 才有批量筛选的「套餐」条件；billing.provider.write 才能调账；metering.reset.read 才出现「流量重置」标签（页头与抽屉），.write 才能手动重置；security.audit.read 才出现「风控」标签与画像里的注册 IP（明文 IP 只在那条接口里）。写操作取 src/admin/actions.ts 的三件，reauth 由外框对话框接管。
待决按「未决前」（一律方案 A）：D-B-2 重置密码是管理员直接设新密码 + 原因，不发邮件；D-B-3 用户组不显示「可用节点池」列；D-B-4 设备识别窗口只读说明 5 分钟；D-B-5 不给全局「默认同时在线设备」滑块；D-B-7 批量生成不带「开通套餐」；D-B-8 设备标签只有在线台数与上限，不列逐台客户端与 IP。

BulkTab.tsx: 「批量运营」标签：筛选（套餐 / 状态 / 到期 / 用户组）驱动的只读预览、导出 CSV（fetch 带 Bearer 取回再存文件，reauth）、群发（主题 + 正文变量，确认后带幂等键）；右栏批量生成（前端预检、幂等、结果只显示一次，本地拼 CSV 下载）
