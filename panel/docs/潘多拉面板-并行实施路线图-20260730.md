当前生产基线：Release 53 / Goose Schema 40 / Linux amd64 与 arm64

## 1. 执行原则

项目按“产品域拆分、接口先冻结、文件所有权隔离、实现与验收分离”的方式并行推进。任何模块只有同时具备真实数据、服务端权限、持久化约束、审计、可操作 UI、自动测试和浏览器证据，才标记为完成。数据库有表、前端有菜单或 API 返回 200 都不单独视为完成。

生产发布始终串行归主线负责：先加密备份，再停写迁移，随后验证运行中二进制、数据库版本、健康探针、登录和关键 API，最后才恢复入口。子任务不得直接修改生产。

## 7. 冻结接口

- 管理员和用户端保持同域统一入口，但继续使用独立认证域和不可互换的 token。
- 管理 API 基址继续从当前自定义路径推导，不在前端写死。
- 收入只允许 CNY 与 USD，任何汇总都不得跨币种相加。
- 工单创建允许只传 `body`，标题和分类由服务端生成；旧客户端字段继续兼容但不要求用户填写。
- 节点上报下一版统一采用 `report_id + sequence + period_start + period_end`；重复 report 必须返回同一 ACK，不重复计量。
- 专属客户端使用独立 client 域，设备授权、设备 token、配置 bundle 和 release manifest 均需签名、过期时间和可撤销状态。
- Rust 用于共享客户端安全核心、签名验证、更新器和测得的热点；云端控制面继续使用 Go，Android UI 使用 Kotlin/Compose。

## 8. 统一完成门槛

每个工作包必须满足：

1. 无越权路径，所有租户数据经过 RLS 或等效范围约束。
2. 高风险写操作要求近期重认证；可重试写操作要求幂等；管理写操作留下同事务审计。
3. 金额使用最小货币单位整数，CNY/USD 独立展示。
4. 覆盖正常、空状态、校验失败、权限拒绝、网络失败、并发和重放。
5. Go 测试、vet、真实 PostgreSQL 门禁、Linux amd64/arm64 构建按风险执行。
6. UI 必须通过手机、平板、1080p、2K、4K 和 Windows 高缩放浏览器验收。
7. 实现者不得自批；独立 agent 审查 P0/P1 缺陷，主线核对真实文件和测试结果。
8. 生产发布前必须完成加密备份、回滚准备、运行中二进制身份检查和关键业务回归。

## 9. 当前已知运维依赖

- Age 解密身份不保存在 VPS；完整备份解密/恢复演练必须在离线受控环境完成。
- 专属客户端签名根密钥、节点配置签名轮换和制品签名尚未落地，不得把未签名客户端更新称为生产可用。
- 当前传统订阅兼容可继续使用；不支持的协议不得通过前端 JSON 绕过服务端稳定 Schema。
