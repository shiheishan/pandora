## 目标

新前端到现在只对假后端验过。第 10.3 节说过：zod schema 是前端和后端对账的唯一防线。本会话在 CI 上起真实的 PG18 + 网关，**用前端页面自己的 zod schema** 去解析真网关的响应。这样查出来的就是「页面拿到真数据会不会崩」，而不是另写一套断言去比较。用户定的顺序是：先用 CI 冒烟挡住接口形状不对的问题，再上测试机人工点。

## 步骤（每步一个提交，做完停下报告）

| 步 | 内容 |
|---|---|
| ① 起栈 | 在 CI 上加一个任务（放进 `panel-pg18.yml`，或者新建 workflow，二选一并说明理由）：PG18 容器 → goose 迁移 → 用 `aegis-adminctl` 建管理员 → 用 CI 里临时生成的配置（不含任何真实值，第 11 条铁律）从源码启动 `aegis-public` 与 `aegis-admin` → 健康检查。复用 `deploy/run-pg18-gates.sh` 与 `tests/*_e2e.sh` 里现成的做法，不另起炉灶。触发路径包括 `panel/internal`、`panel/cmd`、`panel/migrations`、`panel/frontend/src` 和冒烟文件本身 |
| ② 造数据 | 跑一条最小业务链，让各列表都不为空（空数组对 schema 几乎什么都验不出来）：注册与登录门户用户；后台建节点池、登记一个节点并上报心跳（照 `node_e2e.sh` / `uniproxy_e2e.sh`）；向导建套餐并发布（`AEGIS_SALES_ENABLED=1`）；门户下单并用演示渠道支付；工单、公告、知识库、礼品卡、优惠券各造一条 |
| ③ 形状校验 | 在 `panel/frontend/tests/smoke/` 下用单独的 vitest 配置（不进 `make frontend-check`）：以管理员和门户用户两个身份，对前端调用的**每个 GET 接口**，用页面实际使用的那个 schema 解析真实响应。接口清单从 `src` 里的调用处整理出来，写成表，每行标「已验 / 跳过及原因」 |
| ④ 写接口 | 抽样验证写路径：reauth 流程（`reauth_required` → reauth → 重放）、幂等（2xx 同 key 重放、换请求体 409）、每个模块至少一个写操作的响应能被页面 schema 解析 |

## 规则

- `src/` 里只允许一种改动：给页面内没导出的 schema 加 `export`，不改形状、不改页面逻辑。其余一律只动 `tests/smoke/`、CI 与部署脚本。
- **发现不一致不要修**：Go、页面、schema 都不改。把「接口、schema 期望、真实响应片段、判断是后端错还是前端错（按契约）」写进报告，协调会话写成修订、指派给后端三 / 后端四 / 前端收尾。
- 冒烟里不得出现真实服务器地址、域名、密钥（公开仓库，`.githooks` 的 gitleaks 会扫）。
- 后端三、后端四会改接口形状（R99–R104），形状以主线为准：做事前 `git merge feat/panel-redesign`，合进来的新字段让冒烟跟着变。
