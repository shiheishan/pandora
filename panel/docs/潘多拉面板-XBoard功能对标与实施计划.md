# 潘多拉面板 XBoard 功能对标与实施计划

更新时间：2026-08-02  
复核：2026-09-21，第 2 节表格的插件管理、主题管理、礼品卡三行按当前代码修正，其余行未复核。

## 1. 项目目标

XBoard 已有的核心运营能力作为潘多拉面板的最低功能基线。对标的是可执行的业务能力，不复制第三方代码、品牌或页面。每个模块只有同时具备真实数据、权限化 API、持久化模型、审计、错误处理、响应式界面和验收证据时，才可以标记为完成；数据库预留表、空菜单或静态演示不算完成。

潘多拉面板继续保留自己的安全架构：用户端与管理端认证域隔离、管理员路径可配置、租户级 RLS、追加写审计、复式账本、节点身份与配置签名、幂等写接口以及可回滚部署。

## 3. P0：核心经营与交付闭环

### 3.1 经营仪表盘

- 收入只展示 CNY、USD，禁止无汇率混加。
- 财务实际净收入按 `platform_revenue` 全部分录的贷方减借方计算。
- 人工调整使用独立、追加写的报表调整记录，不修改订单、支付或原始账本。
- 同时显示实际净收入、人工调整、展示净收入。
- 支持 7/30/90 天，逐日图和明细表均能对到来源记录。
- 增加月上传、月下载、节点流量排行、用户流量排行、队列健康和失败作业钻取。

验收：任取一天，收入与账本 `credit - debit` 对平，流量与去重后的上报记录对平；不同币种不混加；调整可追溯并只能用反向记录撤销。

### 3.2 Server 与 Node

- 建立独立 Server 资源，承载多个 Node，展示 Agent、架构、系统、心跳、CPU、内存、磁盘和承载数量。
- Server 支持注册、编辑、维护、排空、退役；存在依赖时删除必须返回 409 和影响清单。
- Node 支持创建、编辑、复制、启停、排序和批量操作。
- 协议至少覆盖项目支持矩阵中的 Shadowsocks、VMess、Trojan、Hysteria2、VLESS、TUIC、SOCKS、Naive、HTTP、Mieru、AnyTLS；每种协议由服务端 Schema 校验，不能只信任前端 JSON。
- Node 可选择 Server、权限组、父节点和版本化路由组。

验收：新 Server 注册后 60 秒内显示在线；创建节点并发布后用户订阅可获取，停用后不再下发；错误协议配置在 API 层拒绝。

### 3.3 套餐、订单、用户与支付

- 套餐：版本化 CRUD、CNY/USD 价格、流量、设备数、节点权限组、库存、发布/归档。
- 订单：详情、人工单、取消、补单、退款申请/审批、支付事件和账本钻取。
- 用户：创建/编辑、套餐、到期、流量、批量状态、高级筛选、匿名化与审计。
- 支付：渠道完整配置、加密密钥、回调、币种/费率、连通性测试和安全启停。

验收：套餐发布→用户购买→支付成功→订阅生效→订单/账本/仪表盘一致；退款后收入与权益按规则回退。高风险写操作需要近期重认证、幂等键和同事务审计。

## 6. 统一完成门槛

每个模块上线前必须满足：

1. API 与领域不变量先于菜单开放；不得出现空页面或假成功。
2. 所有查询受租户 RLS 约束，所有写操作做权限检查；高风险动作要求近期重认证。
3. 会产生重复副作用的写操作必须幂等。
4. 管理写操作与追加写审计处于同一事务。
5. 金额使用最小货币单位整数；CNY/USD 独立展示。
6. 覆盖空状态、加载、成功、校验失败、权限拒绝、网络失败和可恢复错误。
7. 实测手机、平板、1080p/2K/4K，无页面级横向溢出。
8. 自动化测试、独立代码审查、真实浏览器验收和部署回滚证据均通过。

## 8. Server / Node 安全拆分第一切片（2026-07-29）

- 新增迁移 `00033_server_node_split.sql`：建立独立物理宿主 `servers`，Node 通过租户内复合外键归属 Server，并启用/强制 RLS。
- 现网 17 个历史 Node 使用同 ID 创建 17 个 Server 并完成精确关联，`server_id IS NULL` 为 0；该策略保持旧 Agent 标识兼容。
- Bootstrap 与 heartbeat 在同一事务双写 Server 与兼容 Node 宿主字段；Node 生命周期变更同步投影 Server 状态和独立 `serving_status`。
- 普通订阅只下发 `Node=active + serving=active + Server=ready + 协议就绪`；canary 可供运维认证但不进入普通订阅，draining 只允许存量收尾。
- 协议注册表覆盖 15 种类型；Shadowsocks v1 已执行严格字段、重复键和版本校验，其余协议暂按只读兼容 v0 运行并列入 NODE-002。
- 历史异常数据采用 fail-closed：协议类型非空但端口为空时状态 API 返回 200，结果为 `draining/disabled/draining`，不报 500、不下发用户配置。
- 迁移 Down 在 Node 重挂、Server 孤儿、多 Node 归属或宿主事实分叉时拒绝回滚，避免静默丢失关系或生命周期元数据。
- 主库已迁移至版本 33；17/17 关联、5 个可订阅 active Node、三服务健康和公网双入口均通过。
- 本切片已通过全量 `go test -count=1 ./...`、`go vet ./...`、空库 1→33、真实克隆库 Up/Down/Up、amd64/arm64 静态交叉编译与独立审查；无 Blocker/Major。
- 第一切片后的 Server CRUD/UI 已在第二切片完成；Node 完整操作与 Server 归属移动已在第三切片完成，NODE-001 关闭；全协议稳定 Schema 仍由 NODE-002 跟踪。

## 9. Server 管理第二切片（2026-07-29）

- 新增真实 Server 管理 API：列表、详情、创建、元数据编辑、生命周期变更、依赖保护软删除及关联 Node 列表；所有查询均在租户 RLS 事务内执行。
- 创建/编辑使用 `node.write`，状态与删除使用 `node.lifecycle`；高风险操作要求近期重认证，写入与追加写审计处于同一事务。
- 元数据与 Agent 上报事实分离：管理员只能编辑名称、地区、地址、架构、系统、容量和备注，不能伪造 Agent 版本、心跳或 CPU/内存/磁盘。
- `row_version` 乐观锁覆盖编辑、状态与删除；过期版本返回 409 和当前版本。删除仅允许已退役且无 Node、活动身份、运行任务及控制节点依赖的 Server。
- ready 门禁要求至少一个通过协议校验的 active/serving Node；状态机前后端一致，退役不可恢复。
- 修复 `last_heartbeat_at IS NULL` 时 SQL 三值逻辑导致 Go `bool` 扫描 500：查询统一 `COALESCE(..., false)`，并以 ready/空心跳真实主库数据回归。
- 管理后台新增服务器统计、搜索、筛选、列表、Node 钻取、编辑与状态操作；动态内容全部转义，按钮权限与 API 权限一致。
- 4K 管理工作区扩展至 3200px，3840×2160 主区利用率 89.5%；390×844、768×1024、2048×1152、3840×2160 均无页面级横向溢出。
- 全量 `go test -count=1 ./...`、`go vet ./...`、amd64/arm64 静态构建、真实 PostgreSQL E2E、RLS 隔离、审计核对、独立审查和公网浏览器验收均通过。

## 10. Node 管理第三切片（2026-07-29）

- 新增真实 Node 管理 API：创建、编辑、复制、Server 归属迁移、显式排序和批量服务生命周期；所有写入均经过 RBAC、租户 RLS、同事务审计，并对高风险动作要求近期重认证与幂等键。
- `nodes.row_version` 覆盖协议、资源池、路由、归属、排序和生命周期修改；过期版本返回 409。批量操作按稳定 UUID 顺序锁定，任一版本或状态校验失败时整批回滚。
- Server 容量在锁定宿主后以第二条查询重新统计，阻断并发超卖；Server 容量也不能降到当前占用以下。控制 Node 通过可延迟复合外键强制属于对应 Server。
- 仅草稿或停用的纯逻辑 Node 可迁移；存在控制关系、身份、运行实例、指标、任务、编排、Bootstrap、配置应用、用量来源或历史流量依赖时全部 fail-closed 拒绝。
- 新建写入只接受已开放的稳定协议 Schema；旧 v0 节点继续只读运行，复制时清空旧协议并返回升级警告，不能通过旧协议或状态接口绕过版本门禁。
- 订阅与 UniProxy 同步区分逻辑 Node 和 Agent 控制 Node：逻辑 Node 由 `serving_status` 门控，控制 Node 还必须通过旧 Agent 生命周期和宿主健康门禁。
- 管理后台提供统计、搜索、Server/状态筛选、创建、编辑、复制、迁移、详情、批量生命周期、排序和退役记录显式追溯；默认不展示退役历史，避免测试或审计记录污染日常运营视图。
- 真实生产 E2E 覆盖稳定协议正例、旧 v0 写入拒绝、显式清空资源池、409 并发冲突、空路由不存在 404、活动节点迁移拒绝、逻辑节点安全迁移、批量原子回滚、排序、控制 Node 迁移拒绝、RLS 和审计。
- 迁移 1→34 空库、生产克隆 Up/Down/Up、全量测试/vet、amd64/arm64 静态构建、原子部署与回滚准备均通过；公网在 390×844、1024×1366、1920×1080、3840×2160 均无页面级横向溢出。
- 生产目录权限已从旧归档遗留的 777/666 收紧为目录 755、源码/静态文件 644、环境文件 600，项目内 world-writable 文件和目录均为 0；三项服务、HTTPS 域名与 7001 入口保持健康。

## 11. 协议与 QNode 对接切片（2026-07-29）

- 当前可新建、启用、认证并下发订阅的稳定协议严格收口为 Shadowsocks、VLESS TCP（`tls=false`）和 VMess TCP（`tls=false`）。
- Trojan、Hysteria2、TUIC、AnyTLS 等依赖完整证书生命周期的类型只允许读取历史记录，在证书签发、轮换、吊销与 Agent 原子应用闭环完成前不得伪装成可服务协议。
- QNode 的潘多拉模式使用 UUID Node ID 与 Bearer Token；身份只进入 query/header，流量、在线与状态正文保持纯业务数据，畸形 Authorization 不得降级使用 query token。
- Nginx 仅对外暴露精确的 UniProxy 与 Node API 前缀，Node 服务继续独立监听内网端口；管理员与用户后台仍由统一入口提供，管理员路径由部署配置隐藏。
- 公网 E2E 已覆盖配置/用户拉取、错误身份、认证降级拦截、在线/流量空批次、资源状态上报和指标持久化。单节点生命周期接口在 E2E 中发现 SQL 组合缺陷，修复、回归、重新构建与部署完成前本切片保持进行中。

## 12. 专属客户端技术路线

客户端采用“Go 云端控制面 + Rust 跨平台核心 + 平台原生界面”，不对现有 Go 面板进行低收益的全量 Rust 重写。

| 层级 | 推荐技术 | 职责 |
|---|---|---|
| 云端面板 | Go | 用户、套餐、订单、支付、工单、RBAC、节点编排、订阅和审计 |
| 共享客户端核心 | Rust | 订阅解析、配置校验、协议/内核抽象、测速、加密存储、更新签名验证和统一错误模型 |
| Android | Kotlin + Jetpack Compose + Rust Core | `VpnService`、通知、后台保活、快捷开关、分应用代理和系统权限交互 |
| iOS/macOS | Swift/SwiftUI + Rust Core | Network Extension、钥匙串、系统代理和原生生命周期 |
| Windows/Linux 桌面 | Tauri + Rust Core | 托盘、系统代理/TUN、自动更新、诊断导出与多窗口管理 |

客户端分期：

1. 先冻结面板到客户端的版本化 API、设备注册、订阅与更新清单签名契约。
2. 建立 Rust Core，所有 FFI 接口使用稳定 DTO，禁止平台 UI 直接依赖具体代理内核内部结构。
3. Android 首发验证登录、设备绑定、套餐/流量、节点选择、连接、故障诊断和安全更新。
4. 桌面端复用同一 Rust Core，再开发 iOS/macOS；每个平台分别完成签名、发布、崩溃恢复和弱网验收。
