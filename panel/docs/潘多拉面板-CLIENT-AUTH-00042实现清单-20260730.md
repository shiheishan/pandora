00042 创建角色时必须设置以下 exact shared-object comment：

```text

```

Up 前若同名角色已存在：

- 任一冻结属性不符立即拒绝；
- comment 以 `pandora:aegispanel:migration=00042;` 开头立即拒绝，避免复用另一个数据库的 00042 角色；
- 其他 comment（包括 NULL）必须原样保留，00042 不修改该角色。

`app.client_auth_00042_meta` 增加三个非 secret provenance 列：

```sql
role_creation_mask smallint
  CONSTRAINT ca42_role_creation_mask_nn NOT NULL,
CONSTRAINT client_auth_00042_meta_role_creation_mask_check
  CHECK (role_creation_mask BETWEEN 0 AND 15),
role_oid_manifest jsonb
  CONSTRAINT ca42_role_oid_manifest_nn NOT NULL,
catalog_manifest jsonb
  CONSTRAINT ca42_catalog_manifest_nn NOT NULL
```

bit 0–3 按本节角色清单顺序对应四个角色。Up 必须在角色 DDL 前计算 mask；角色创建、marker 和 meta insert 在同一事务。marker 只是 mask 的辅助完整性标记，不是授权或安全凭据，绝不能单独决定 DROP。

`role_oid_manifest` 必须是恰含上述四个角色名的 JSON object，值是 Up 锁内首次确认/创建后的 cluster role OID。它与 `role_creation_mask`、exact marker 一起构成角色身份 provenance：Up post、Down guard 和每次最终 DROP 前都必须满足 `name + OID + mask + marker` 一致；同名同属性角色在迁移周期内被删除重建也必须拒绝。OID 只允许出现在该专用 provenance 字段，不进入可跨 clean cycle 比较的通用 catalog 快照。

`catalog_manifest` 不是可编辑配置。Up 在全部 00042 DDL、RLS 与 REVOKE 完成后，生成格式名 `client-auth-00042-catalog-v1` 的 OID-free JSONB 快照并写入；最终列无 default。快照必须精确覆盖 meta、四张既有表、八张新表和两条 identity sequence，共 15 个 relation，且包含 schema/name/kind/persistence/owner、RLS、列名与顺序/类型/typmod/NULL/default/identity/generated/collation/storage/compression/列级 ACL、具名 constraint 的类型/列/定义/validated/deferrable、全部 index 定义及 valid/ready/live 状态、policy、内部与外部 trigger、relation ACL、sequence 参数和 identity internal dependency。Down 在固定锁内逐 relation 重算并与快照做 JSONB exact equality；缺项、重复项、格式漂移、同数量替换对象、invalid/expression index、列级授权或快照 envelope 变化均整事务拒绝。该快照不包含业务行、secret、OID、ctime 或 password verifier。

Down 按以下四分支逐角色处理：

- mask bit=1 且 comment=exact marker：完整属性/依赖门通过后才允许 DROP；
- mask bit=1 且 marker 缺失或变形：拒绝；
- mask bit=0 且 comment 使用 reserved prefix：拒绝且不 DROP；
- mask bit=0 且 comment 不使用 reserved prefix：保留且不修改。

任一角色缺失、属性/ACL/dependency 不精确均拒绝。`SET LOCAL createrole_self_grant=''`，创建前后均断言 membership 为零。

advisory lock 只在目标数据库内生效，不是 cluster-wide 锁。外部 runner 必须先枚举 `datallowconn=true AND datistemplate=false` 的数据库；除目标库和显式维护库 allowlist `postgres` 外逐库连接检查 `public.goose_db_version`、`app` schema 和 `app.client_auth_00042_meta`。任一库不可连接、枚举不完整，或另一库包含 Pandora goose/app/00042 证据，均以环境不合格 `exit 78` 结束，且目标库零 DDL。

## 5. issuer 与 kid grammar

`client_access_token_jtis.issuer` 的数据库局部门冻结为：

```sql
octet_length(issuer) BETWEEN 9 AND 261
AND (issuer COLLATE pg_catalog."C") ~ '^https://[a-z0-9](?:[a-z0-9.-]{0,251}[a-z0-9])?$'
```

## 8. 审查拒绝门
