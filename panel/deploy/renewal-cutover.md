# 续费幂等切换闸门

当前结算服务只接受同时满足以下条件的续费订单：

- `idempotency_key_id` 非空；
- `business_request_id = idempotency_key_id`；
- 对应幂等记录已按租户、用户和 `subscription_renewal_create` scope 绑定。

`check-migrations.sh` 会在维护窗口内、全部写服务停止后、生产迁移开始前执行只读检查。只要发现 `draft`、`pending_payment`、`processing` 或 `paid` 状态的旧续费订单缺少精确关联，发布就以退出码 78 停止。检查只输出数量，不输出用户或订单标识。

## 处理原则

1. 保留发布前的加密数据库备份，不要用 SQL 直接修改订单、优惠券、余额冻结或预留状态。
2. 对没有任何支付、支付事件或外部到账证据的 `draft`/`pending_payment` 订单，使用现行应用的普通取消订单流程处理；该流程必须原子释放优惠券、余额冻结和父预留。
3. 对 `processing`、`paid`，或已存在支付/支付事件/异常到账证据的订单，停止发布并逐单对账。确认支付渠道事实后，走经审计的人工退款或专门的补偿结算流程；不得伪造幂等记录，也不得把旧订单直接标记为 fulfilled。
4. 重复运行 `check-migrations.sh`，只有出现 `renewal cutover active_legacy=0` 才允许继续发布。
5. 切换后保留发布收据、备份哈希、闸门输出和人工对账记录；任何数量不确定、查询失败或状态变化都按发布失败处理。

此闸门不会自动取消订单或处理资金。它只证明新结算代码上线时不存在无法安全结算的活动旧续费单。
